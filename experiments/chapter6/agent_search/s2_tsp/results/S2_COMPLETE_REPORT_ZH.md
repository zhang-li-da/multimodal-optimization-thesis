# S2 TSP 实验总报告

本轮完成了两个连续但独立冻结的 MiniMax M3 TSP 实验：P1 保护因子筛查和 P1b 输出修复后的机制曝光筛查。两批次均保留原始请求、响应、usage、候选程序、评价、test 结果和文件哈希；P1b 没有覆盖 P1。

## 研究流程

P1 使用 planner/coder 上限 1800/2000，24 个 job、192 个提案。结果显示 170 个 planner 响应因 MiniMax 推理内容占满上限而没有完整 JSON，只有 19 个候选有效，保护机会几乎不存在。P1 平均保护组与未保护组 Test gap 差为 `-0.00033` 个百分点，但这不能作为保护效果证据。

P1b 在新数据块 20--23 上预先提高 planner/coder 上限至 4000/2400，16 个 job、192 个提案。有效候选增加到 114 个；保护组兑现 14 个开发时隙，6/8 个配对出现保护开发，说明输出瓶颈修复后执行链可以运行。但多分支同时可选只出现在 1/8 个配对，未达到冻结协议规定的曝光门槛。

## P1b 主要质量结果

| 控制器 | 平均 Test gap | 平均 tokens | 配对胜负 |
|---|---:|---:|---:|
| `fb_unprotected` | 4.9465% | 64,976 | 4 |
| `fb_protected` | 5.0662% | 66,552 | 4 |

保护组减去未保护组的 8 个 block-seed 配对平均差为 `+0.1196` 个百分点；描述性 bootstrap 95% 区间 `[-0.4507, 0.6970]` 个百分点。保护组平均 token 更高约 2.4%，没有显示相应质量收益。

## 科学结论

目前可以成立的结论是：

* MiniMax M3 可以在提高输出上限后稳定地产生可评价的受限 TSP 程序。
* 有限开发额度账本能够在真实搜索中安排、扣减并审计后续开发机会。
* 当前单模型、TSP14、12 提案预算下，保护机制没有建立相对简单未保护基线的质量优势。

目前不能成立的结论是：

* 保护机制、关系排序或反馈调度具有稳定增量；
* 五策略优于单路径、广泛重启或固定开发；
* 多模态程序集合具有部署收益；
* 方法可以跨模型或跨任务泛化，或已经足以收口博士论文第六章。

P1b 的主要剩余问题不是输出完整性，而是多分支机会仍然稀少。因此，直接扩展五策略会把“机制没有被检验”与“方法没有效果”混在一起。后续若继续，应先做独立的机制控制用例或更长且统一总预算的曝光实验，并在协议中预先要求多个配对出现至少两个同时可选分支。若充分曝光后保护仍无增量，应删去保护优势主张，围绕可审计的有限分支开发和负结果重写第六章。
