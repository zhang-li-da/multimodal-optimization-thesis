# 阶段 B 续开发修订

公共前缀显示 MiniMax-M3 的完整请求经常超过原 180 秒期限，因此续开发使用最多
600 秒的单请求等待，并始终服从每任务 900 秒 wall、100,000 token 和 16 请求上限。
请求失败不重试，未知成本不填零，服务过载会暂停后续派发。

EG 的历史摘要增加可核对的方向证据：节点、父代、意图、标签、程序和结构身份、
validation 质量、有效性与失败类型。缺少显式 strategy_hypothesis 只标为缺失证据，
不能被解释为方向无效或零收益。摘要仍只读取检查点前已观察的 search/validation 数据，
不读取 Test，也不增加摘要模型调用。

四种续开发行动、两次重复、每任务 8 个提案、检查点 4/8 选择规则、模型输出上限、
评价器和候选冻结规则均保持不变。第 24 步不可用的三个检查点不补抽；对应任务终态
为 preparation_incomplete。可用的 13 个检查点形成 104 个真实任务。

这是一项基于公共前缀执行证据的工程修订，不是根据 Test 结果调参。续开发仍是诊断
实验，不能单独证明 G/P/F 或完整方法有效；Test 只能在全部任务终态和候选冻结审查后开放。
