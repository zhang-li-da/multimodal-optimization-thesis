# 续开发期间的分析修订与后续方法约束

本修订形成于 r3 注册段执行期间，只新增离线分析，不改变运行中的源码、提示、项目身份、行动顺序、阈值、预算或检查点。本轮延续既有 I/B/E0/EG 诊断；不执行阶段 C/D/E，不开放 Test。分析定义属于看到部分 validation 轨迹后的补充诊断，不能伪称事先冻结的确认性终点。

## 当前可以落实的完善

稳定 investment 身份已在真实 B 与 EG 轨迹运行。项目跨越行为簇后仍可由项目历史最好后代继续开发；行为分类本身不创造新额度。审查同时检查进步后下一步父代、investment 身份、跨簇情况和全局收益。触发/连续性只说明机制按定义执行，不能说明有净增量。

新增 `investment_outcomes.py` 为所有行动使用同一搜索目标：第 h 步前缀可选的最好 validation loss，相对共同检查点 incumbent 的下降量。保留初始 incumbent，所以该量非负；B 相对 I、EG 相对 E0 的配对差可以为负。项目内追赶次数另列，不能进入全局收益分子。

E0/EG 的成本包含失败的探索、有效起点生成及随后开发，均从任务首个请求累计。4 步和 8 步是嵌套观察窗口，不能相加；第 5–8 步的增量由两个累计窗口相减，只记一次。未达到窗口记缺失；用量未知时不计算收益/token。预算质量比较和实际成本均需单列：共同上限不是严格等 token。完整任务额外失败成本始终保留在累计账本，不能被较早窗口隐藏。

只比较相同检查点、重复编号、观察窗口的已冻结结果。全部 128 行及缺失原因保留；同区块检查点和模型重复先汇总为区块均值，不当成独立区块。当前缺少完整配对时不产生组间结论；只完成部分配对时也必须报告覆盖偏差。

## 两个不能靠当前轨迹声称已解决的问题

1. EG 的历史摘要有程序意图、质量、失败记录，但公共前缀缺少结构化策略假设。EG 生成时要求的四字段假设并不能追溯补全过去的历史。当前诊断是实际已有历史信息的效果；若未来完善历史表示，必须另定生成/持久化契约和版本，不修改冻结前缀。
2. F 仍未验证跨行动预测价值。项目内进步可作续期辅助信息，不能直接与 incumbent 的全局改善/token 比大小。新的统一分析只能提供诊断标签，不自动变成可靠预测器；C 前需独立验证，不因局部成功直接增加保护预算。

## 执行风险与下一版边界

r2 的最后一次 planner 在任务剩余约 4.71 秒时发出，随后遇任务 wall 超时并留下未知用量。没有业务码/HTTP 证据支持把它归因于额度耗尽。当前 r3 保留 900 秒任务和 600 秒请求规则，不能在执行期间更改。

后续执行修订应为请求设置事先冻结的最小可用 wall 预留；不足时在发送前返回 `budget_exhausted`，保留已经完成的候选，不生成 `sent_unknown`。预留多少秒尚未冻结，不能根据哪个动作的结果好坏选择。它不能保证调用必定成功，也不能成为扩大任务时间、重试旧任务或绕过暂停的理由。

已实现可选字段 `minimum_request_wall_seconds`：只在未来 manifest 明确给值时启用，值必须有限且位于任务 wall 上限内。当前 r3 没有该字段，执行版本仍为 `228a607`；不追溯启用，也不把测试使用的 30 秒视为科学参数或验收值。

研究方法暂不新增调度模块。下一次是否保留 G、P 或加入 F，应由完整比较决定；无增量可删减，证据不足如实保留。当前公共前缀和续开发中的 validation 下降均不确认 H1–H3。

离线验收为 `test_investment_outcomes.py` 与 `test_audit_segments.py` 共 8 passed：覆盖局部追赶不冒充全局收益、未来结果不能进入早期窗口、未知成本/删失不填零、区块等权汇总，以及真实历史归档的逐层审查。首次测试收集遇相对导入错误，修正为绝对包路径后通过；未发生模型或 Test 调用。

可选时间预留修复的验收为 `test_wall_admission.py` 与 `test_phase_b_runner.py` 共 14 passed；包括近期限拒绝、历史 manifest 保持原行为、边界值和非法参数，以及原有阶段 B 执行语义。
