## 科学问题与贡献边界

研究问题是：在有限生成和评价预算下，智能体怎样发现潜在优质方向、给予有限试用，并依据实际进展和机会成本决定继续投入、暂存或退出，从而提高最终解质量或预算效率？研究对象是智能体作出的外层行动及其投资轨迹；生成的程序、计划和开发轨迹是这些行动的产物；TSP 路线、机器学习参数等属于任务内部空间。行为簇变化不自动代表新方向，项目数量、分支数和局部改进数也不构成效果证据。

A/B/M 是组织方式，不单独构成创新。A 维护方向档案，保存可验证的策略假设、代表程序和行为证据；B 维护有上限的开发投资；M 记录状态、尝试、失败、成本、成熟延迟收益及全局收益。待筛查的组件为 G（历史信息方向生成）、P（项目身份下有限试用与有条件续期）、F（按成熟收益和机会成本分配预算）。公式、状态转移、合并/改假设/退出规则、决策表和伪代码均以同目录 `METHOD_ZH.md` 与 `controller.py` 为准；任何一项缺失，阶段 A 不通过。

冻结假设如下。H1：在相同接口和资源下，G 比无父代且无历史信息的 E0 更容易产生有效、接近 incumbent 的起点，并改善后续收益。H2：P 能保留部分暂时落后但仍值得开发的方向，且收益超过被替代行动的机会成本。H3：在相同冻结资源上限下，F 相对强简单固定分配提高最终单程序 Test 质量；本章不预注册预算效率主张。H4：经支持的最小组合在独立数据、更宽外层决策空间和另一任务载体仍有可解释作用。阶段 B 是起点/期限诊断，阶段 C 是自然搜索组件筛查；它们只估计和筛查，不确认普遍效果或判 H1–H3 支持。H4 只有在阶段 D 得到支持后才能进入阶段 E 检验。

每项正式假设最终只用四类结论。先把效应变换为正值有利于方法，再为终点预注册实际门槛 `δ`：本章 TSP Test gap 固定 `δ=0.3 pp`，H4 每个新任务/范围必须在进入 E 前冻结质量单位和自己的 `δ`。**支持**要求预注册多重比较校正区间下限 `>= +δ`；**有害**要求区间上限 `<= -δ`；**实际收益不足**要求区间完全落在 `(-δ, +δ)`；其余为**证据不足**。主方法比较定义 `benefit = TestGap(baseline) - TestGap(M*)`，留一组件比较定义 `benefit = TestGap(M*−component) - TestGap(M*)`，二者均为正值有利。H1 还要求 G 开启提高有效近 incumbent 起点率，区间下限 `> 0`；H2 还要求成熟续期净机会收益区间下限 `> 0`。对 H1/H2，分别报告 Test 效应的四类结果和联合假设结论：联合假设只有在过程门与 Test 效应都满足支持条件时才支持；Test 效应达到有害门槛时判有害，区间完全位于实际收益不足范围时判实际收益不足；其余情形（包括过程门失败/不可估但 Test 结果指向正收益，或 Test 精度不确定）判证据不足。阶段 B/C 的点估计不得单独升级为“支持”。若某组件在 C 被删除，对应假设保留“证据不足”且没有 D 级独立确认，不把开发筛除解释成组件无效。H4 在未进入阶段 E 时标为未检验，不可判作通过或失败。

对 G/P/F 消融开关分别记录“条件被触发”和“在相同状态下相对关闭组件实际改变了行动”，两者不可混报。关闭组件不适用的状态单列。回放只证明代码在历史输入上的确定行为和决策差异，不得把旧后代说成新提示、新父代或新调度产生的反事实性能。

## 阶段 B：方向质量与开发期限诊断

使用 B 候选池中的 8 个新区块 60–67，每区块仅跑一个统一 SP 公共前缀，最多 24 proposals；该策略固定为持续开发当前 validation incumbent，不含 G/P/F，不按结果改写。第 8 和 24 提案处冻结同一轨迹检查点，共 16 个检查点。前缀成本单独汇报。

每个检查点随机化后运行 I、B、E0、EG，各 2 次、每次最多 8 proposals，共 128 个续开发任务。I 开发 incumbent；B 开发预先冻结的、质量接近且行为不同的公共前缀候选；E0 无父代且无历史摘要生成；EG 使用搜索期已知历史的固定摘要生成。G 组除历史上下文外，模型、system、接口、评估器、温度和输出边界相同。摘要不得包含 Test 信息；摘要调用、维护和输入 token 成本必须记账。EG/E0 的具体提示差异由冻结 METHOD 文件确定。

检查点选择规则固定为：incumbent 是公共前缀内 validation 最低的有效程序；B 是非 incumbent 的有效候选，validation loss 差在 `(0, 0.035]` 且行为距离 `> 0.08`。不满足条件时如实记 B 不可用；不替补、不补抽检查点。行为距离只作入选条件，不被解释为不同决策方向。I、B、E0、EG 的 lineage 和 proposal 规则执行冻结 METHOD。

EG 历史摘要由本地确定性序列化产生，不另作模型摘要请求；摘要实际进入 planner 的 token 数随 provider 返回的 `input_tokens` 记账，序列化 CPU/wall 时间单独记录。若未来加入模型压缩摘要，则必须把该请求作为独立 action 和成本纳入所有组的一致对照，否则不得执行。

每条四组轨迹在第 4 和第 8 提案各冻结一个 validation 最佳程序（无有效后代时冻结起始候选并标识回退/缺失）。所有 128 个任务终态和 256 个前缀候选冻结检查全部通过后，再对这 256 个候选统一 Test；另对 16 个检查点的 I/B 起始参考候选开放同规则 Test，最多增加 32 个程序。Test 工作量上限为 288 程序 × 60 test instances = 17,280 个实例级评价；B 不可用的参考候选不计。每个区块初始化 3 个共享 seed，它们只在 8 个 SP 公共前缀中各评价一次，不计入 proposal 数、模型请求或 token。proposal 搜索评价上限为 (192+1,024) proposals × 48 probe/validation instances = 58,368；加上 8×3×48=1,152 个seed评价后，B 搜索评价总上限为 59,520 个实例级评价。

分析以区块为单位：先聚合每块内重复和两个检查点。阶段 B 全部对比均为诊断估计：EG−E0 的首个探索提案有效且 gap≤0.035 的比例、首提案 validation gap、第 4/8 步 Test 质量和成本；I、B 作同检查点机会成本参照。B 不可用频率、条件 B 比较与 B 不可用回退 I 的全状态比较分开。报告结构变化/行为变化、局部进步转成全局与 Test 进步的比例、预算交互、token/请求/时间以及区块集中度。所有区块与终点均列出；不以阶段 B 的 p 值、区间或点估计宣布 H1 支持。少区块导致区间很宽时明确为精度不足。

## 阶段 C：自然搜索组件筛查

只有阶段 B 诊断和阶段 A 验收完成后，才能冻结候选 M*；阶段 B 修改出的提示或门槛仍属于开发产物。阶段 C 使用独立开发块 68–71，每块 2 个嵌套重复，6 组共 48 次搜索。所有组请求同一模型、接口、评价器和执行沙箱；每次搜索共同上限 300,000 已知 token、64 个 proposal 安全上限、3,600 秒 wall 上限和最多 128 次请求尝试。任何组先触发上限即结束该次任务，不补齐或追加。模型失败按相同 terminal/fallback 规则留档。

组别定义：SP 为 incumbent-only 单程序持续开发；FIX 为强固定分配多分支基线，每 4 个静态 proposal 槽按 I,I,B,E 轮转（长期 I/B/E 为 32/16/16 槽），维护各 action 的 validation 最佳代表，B 选非 incumbent 的可用代表；固定 B 不可用时该槽转给 I；E 槽生成无父代方向并纳入代表档案，之后能被固定 B 槽开发。该基线不按收益自适应改变份额，不以已知缺陷实现充弱对照。FULL 为冻结候选 M*=G+P+F；FULL−G 唯一移除历史信息方向生成，E 回到 E0；FULL−P 唯一移除投资身份、有限试用和条件续期，回退为档案代表的静态 I/B/E 使用规则；FULL−F 唯一移除收益/机会成本调度并采用同 FIX 的冻结 I/I/B/E 次序。若实现审计证明 FIX 与某消融动作决策完全相同，该两组需在真实调用前合并，并修订请求预算，不得当成独立比较。

预算、提示上下文和 proposal 数须公平：消融节省的 token/proposal 容量留在同一策略内按冻结替代规则用尽或受公共预算上限限制；记录计划/实际使用、预算利用率、活跃竞争机会、每一开关触发与实际改变动作数、试用/续期/提前退出、续期后增益、成熟/未成熟延迟收益、重复/停滞投入和最好程序产生路径。主要终点为固定资源预算下最终单程序 Test gap；质量、成本优势和兼得分别判定。仅用区块单位区间，不从 FULL 最佳推断组件协同；组件协同要另设预先定义的交互实验。

C proposal 搜索评价上限为 48 searches × 64 proposals × 48 probe/validation instances = 147,456 个实例级运行；每次搜索另评价 3 个共享 seed，增加 48×3×48=6,912 次，本阶段搜索评价总上限 154,368。最终 Test 上限 48 × 60 = 2,880 个实例级运行。仅阶段 C 中的测试会在全部 48 次搜索终态且程序冻结后批量开放。

## 阶段 D：独立确认与样本量

只有 C 能选择出一个固定 M* 且状态完整，才设计 D；若候选无增量、资源不足或服务质量不支持完整数据，停止扩张，形成负结果和简化结论。D 的独立候选区块池仅为 72–111；库存证明无精确坐标冲突不代表已冻结或独立确认，必须在 C 后根据所需区块数重新冻结数据和 SHA。

主终点是固定 token/proposal/wall 预算下、按 validation 选出的最终单程序 Test gap。两个主比较是 M* 对 SP、M* 对 C 中最强简单多分支基线；TSP 实用门槛固定为绝对 0.3 个百分点（gap 比率 `0.003`），伤害门槛对称为 `-0.3 pp`。统一把效应变换为正值有利于 M*：`benefit = TestGap(baseline) − TestGap(M*)`。定义 `ΔC = TestGap(M*−C) − TestGap(M*)`，正值表示保留组件 C 有利；支持须该区块级校正区间下限至少 +0.3 pp，有害须上限至多 -0.3 pp，实际收益不足须区间整体位于实用/伤害门槛之间。G 的 H1 主张另要求 G 开启的“有效且 gap≤0.035 起点率”区块差区间下限大于 0；P 的 H2 主张另要求成熟续期收益率减同一时点最佳已观测替代行动收益率的区块差区间下限大于 0。相关过程差值与所有保留组件 Test 差值共同进入预先冻结的组件 Holm 家族。F 只作固定资源上限下的质量主张，成本单列，不转为效率主张。阶段 B/C 不判组件支持。若组件在 C 被删除，对应假设为证据不足且不纳入 D 独立组件确认。独立确认前按 C 开发数据的区块级配对差值方差计算 N；不得按实例、proposal 或请求计样本。双侧族错误率 0.05 对两个方法主比较用 Holm 控制，功效至少 80%。区块重复数固定为每个方法×区块 2 次并先在块内平均；禁止根据中期 p 值或接近显著补跑。D 方法矩阵至少含 SP、最强 FIX、多次重复 M* 和 M* 中仍保留且承载论文主张的组件消融；报告预先冻结的所有比较。

本协议保留“收益校正区间下限至少 0.3 pp”的确认门槛，它不同于“相对零检出真实 0.3 pp 收益”。前者的正态边际功效近似为 `N = ceil(((z[1-alpha/(2*m)] + z[power]) * sigma_block_pp / (delta_A_pp - 0.3))^2)`，需预先指定 `delta_A_pp > 0.3`（量纲均为百分点），不能继续以 0.003 作该目标的分母。两项主要比较取 m=2、alpha=0.05；须在 D 前明确边际或两项同时成功的联合功效，并以冻结的 t 计算或模拟验证。预期真实效应、独立开发区块方差、精确 N 和预算均待冻结；本轮不读取历史 Test 来调整门槛或计算虚构 N。超过 40 个预留块时另行审查数据与资源，不能自动扩大样本；不足时明确为估计性结果。
