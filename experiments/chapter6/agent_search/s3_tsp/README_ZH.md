# S3：方向保护与探索—开发调度实验

本目录实现第六章下一轮单模型 TSP 实验。研究对象是生成受限 TSP 构造程序的外层搜索过程；“方向”操作化为固定 probe 上执行路线行为的邻近簇，不等同于真实优化盆地或语义算法类别。

## 研究问题

本实验分开回答三个问题：

1. 固定 50:50 搜索中，给质量合格的新行为方向有限的后续开发机会，是否优于相同准入规则但不保护？
2. 保护条件相同时，随预算推进调整探索—开发比例是否优于固定比例？
3. 单路径和广泛重启这两个简单端点，如何界定多方向协同搜索的适用位置？

第六章的暂定方法贡献应限于“有限执行反馈下的方向试用与预算调度”。本实验是 TSP14 单模型筛查，不能单独支持跨任务或通用算法发现主张。

## 方向与开发池

方向成员由 probe 路线行为距离不超过 0.08 的连通关系确定。候选的 planner 标签和粗 AST 描述不决定方向身份；粗 AST 特征只作为诊断记录。方向变更和谱系身份分开维护：从已有方向开发出的新行为方向继承父代谱系的累计额度；无父代探索得到的新方向建立独立谱系。每条谱系最多获得 8 个提案时隙，不能通过换标签、改写代码或重新入池重置。

共享手写种子用于方向匹配和质量基准，不预先占用 B 的保护额度。有效且相对共同初始最好规则达到质量容差的候选，可按两种情况申请额度：

- 新的 probe 行为方向获得一次有限试用；探索候选没有父代也可以准入。
- 已有方向中的候选只有在改善该方向当前代表时才可续期。

每次准入或已验证的方向内进步最多增加 2 个排队时隙；方向谱系累计不超过 8 个。B 容量为 6；满载时只淘汰没有未兑现保护额度的条目，谱系账本继续保留，避免重新入池重置额度。若所有条目仍有保护时隙，则拒绝新条目并记录原因。

一次保护时隙代表一个提案位置，不保证有效程序。无效程序、解析失败或截断响应仍消耗该位置，不自动修复或补跑；报告分别列出请求、完整响应、截断、有效程序评价、局部改进和全局改进，避免把模型请求数误报为有效开发数。

## 策略组

| 组别 | 预注册策略 |
|---|---|
| SP | 每步修改当前 validation incumbent，不重启、不使用 B |
| WR | 每步从无父代探索，不续开发 |
| FB_U | 固定 0.5 探索概率；同样登记候选方向，但不兑现 B 保护时隙 |
| FB_P | 与 FB_U 相同的准入和固定调度，额外兑现有限 B 保护时隙 |
| TS_P | 保护开启；开发概率由 0.15 线性升至 0.85 |
| AD_P | 保护开启；在两个提案为一组的等长单元中调整探索/开发分配 |

AD 前两个完整单元以随机顺序各覆盖一次探索和开发，之后依据每个完整单元的全局 validation-best gap 改善/千实际模型 token 的算术均值计算开发概率：

`p_develop = 0.5 + 0.25 * clip((mean_develop - mean_explore) / (0.001 + abs(mean_develop) + abs(mean_explore)), -1, 1)`。

概率范围固定在 [0.25, 0.75]。两类单元使用相同的全局质量目标、提案数和 token 分母，不把探索发现率与父代改进率直接相减。token 用量未知的单元不用于更新动作均值；缺少任一动作的有效均值时回到 0.5。保护强制时隙不计入 AD 的自适应单元，避免其改变单元长度。

标签、方向数和结构描述不进入主评分。普通开发统一选择当前 validation incumbent；B 的保护队列采用 FIFO，因此保护效果不与复杂的方向排序混在一起。

## 实验设计

冻结协议为 8 个新数据块（24–31）× 6 组 = 48 个搜索任务。每个区块内各组使用同一外层随机种子。每个任务最多 32 个提案、64 次模型请求、300,000 token 和 3,600 秒。planner/coder 输出上限恢复到 S1 已用的 16,384/8,192，温度 0.7。没有自动重试；失败任务保留，不替换。

主质量指标是 validation 选出的单一最佳程序在 test 上的 gap。保护效应为 `FB_P - FB_U`；时间/反馈调度增量分别为 `TS_P - FB_P` 与 `AD_P - FB_P`。差值为负表示左侧组更好。区块是统计重采样单位；实例数、提案数和模型请求数都不是独立搜索重复。

预设 0.3 个百分点作为最小实际收益参考、10% 作为 token 增幅参考。8 个区块只用于筛查，采用按区块 bootstrap 的描述性区间，不做确认性 p 值。任何正向结果都需要后续冻结方法、全新区块和足够样本的独立确认。

测试数据快照不进入搜索 evaluator 或模型提示。所有搜索任务到终态或明确记录停止后，`test-all` 才评价冻结 readout。模型调用记录、请求和原始响应按任务持久化，可从 checkpoint 重放控制器决定。

## 执行顺序

1. 执行 `python -m pytest -q experiments/chapter6/agent_search/s3_tsp`。
2. 从归档 ZIP 生成 P1b 独立复核补记：`python -m experiments.chapter6.agent_search.s3_tsp.audit_p1b --output experiments/chapter6/agent_search/s3_tsp/results/p1b-audit-20260927`。
3. 使用 `study.py prepare` 生成临时 draft，核验区块和数据哈希；提交并冻结代码后再 `study.py freeze`。
4. 先运行一次 MiniMax M3 connectivity preflight；通过后执行冻结清单中的 48 个任务。
5. 全部任务结束或显式停止后运行 `test-all`，随后运行 `analyze.py`。
6. 保留所有计划任务、状态、测试文件和原始请求响应；分析不得新增模型调用。

完整机器协议见 [protocol.final.json](protocol.final.json)。每阶段运行和失败处理以 manifest 为准。
