# r2 实例快照与跨平台数值复核规范

`results/mechanism-only-20260924/r2_instances.json` 保存3个区块、每块108个实例的城市坐标、实例ID与family，共324个实例。它是在原生成环境按冻结代码**事后重建**的；9个split的JSON指纹逐一匹配原manifest。它不是在r2模型搜索时同时保存的快照。

`verify_numeric.py` 使用该快照，直接从发布ZIP读取候选源码，复算198个validation评价与132个test评价。原r2严格验证器和原verification记录保留原样。新增验证器每次要求新输出路径，禁止覆盖归档记录，并拦截网络和模型客户端调用。

比较规则：

1. 路线顺序、最终/probe行为、轨迹行为、合法性、程序hash、AST节点数、特征调用数、局部检查次数、失败类型等离散字段要求完全相同；不以“等价路线”宽松替代。
2. 仅对loss、逐实例loss/value、family loss和trajectory values允许 `abs(a-b) <= max(1e-12, 1e-10*max(abs(a),abs(b)))`，并记录每一个不精确相同的数值、字段路径、绝对误差和是否过界。非有限值、缺字段和结构差异直接失败。
3. wall/cpu用时受机器影响，记录但不要求相同；其它字段不能凭印象忽略。
4. 使用复算的评价重新推进原控制器，标签、父代、参考、操作、allocation、准入、碰撞、信用和深度必须一致。小数误差即使处于容差内，只要改变决策也不能通过。
5. 同时报告严格相同数与符合数值规范数；不把数值容差通过改写成逐位相同。

本次只有Windows本机记录。用户提供的另一环境抽查约2.2e-16误差及提交b4304f5未存在于当前工作区；不能据此认为该环境全部差异已经核验。请在另一电脑保存新的复核文件，再逐项检查。上述容差是本次提出的复核规范，不是r2原预注册门槛，也不用于改变搜索时的有限签名判定。

```powershell
python -m chapter6_demo.v12_1.verify_numeric --output numeric-replay-other-platform.json
```
