# 第六章 Agent Demo：交付结果与科学判断

**已完成真实模型驱动、可以继续运行的多模态程序搜索 agent。工程可行性获得支持；关系记忆的稳定增量和博士章节的完整创新性，当前实验尚未证明。**

最直接的入口是 [交互演示](dashboard.html)。它展示全部 74 次运行，可以切换生成模型、任务和控制器，查看模型生成的代码、搜索过程、跨分支引用、重复行为，以及具体的路线、装箱或分类结果。完整数据见 [实测报告](results/measured_report.md)，运行方法见 [README](README.md)。

## 已完成的工作

Agent 的闭环是：模型提出规则 → 模型编写 Python 函数 → 固定协议执行和验证 → 更新质量档案与执行记忆 → 决定继续、引用、重启或重新激活。有效新候选均包含真实模型产生的可执行代码，生成或执行失败的尝试也计入预算和日志。

这里的“多模态”指多模态优化中的多个高质量行为模式。外层搜索对象是能处理一组实例的算法规则，内层才是规则在某个实例上产生的路线、装箱方案或预测。

| 完成项目 | 结果 |
|---|---|
| 正式运行 | 74 次，均有完整结果、配置、模型交互和 checkpoint |
| 候选生成 | 888 次真实生成尝试；865 个有效，23 个失败；有效率 97.41% |
| 正式实验模型调用 | 1,775 次有 usage 记录的调用，共 2,563,223 个输入与输出 token |
| 生成模型 | Qwen3.7-Plus、MiniMax-M3；GLM-5.3-Flash 另做了连通性检查 |
| 任务 | 12 城市 TSP、64 物品在线装箱、Iris/Wine/Breast Cancer 上的分类规则发现 |
| 机制对照 | quality、niche、terminal、relational；另有去掉轨迹 W 的消融 |
| 科学协议与执行器测试 | 19 项通过 |
| 保存结果回放 | 244 个不同“最终程序—数据划分”组合精确匹配，0 个失败 |
| 界面检查 | 74 次运行全部载入；任务切换、代码选择、分类结果与模型切换通过；没有 JavaScript 异常 |

888 次生成原本最多对应 1,776 次 planner/coder 调用，其中一次 planner 返回的 JSON 不是对象，未进入 coder；该次失败已计入候选预算。表内统计只包含四组正式 pilot 实验，连通性探测和早期开发数据不混入结果。API 费用不是本次实验的限制，仍记录实际 token，以便公平评价搜索效率。

## 多模态优化机制如何进入 agent

- **A：质量约束的行为档案。** 先要求规则损失接近当前已发现的最好规则，再按固定 probe 上的执行行为去重，保留多个代表。TSP 使用路线边关系，装箱使用共箱关系，分类使用预测类别向量。
- **W：中间执行证据。** 保留构造/局部改进过程中的状态或固定序列前缀，供互补引用使用。分类任务的 W 是样本预测前缀，还不是训练动力学轨迹。
- **M：意图与实际结果的关系记忆。** 记录目标策略族、代码实际行为、重复、改进、失败和成本。调度按历史改进、重复率与探索项分配后续候选机会，并保留重新激活机制。

当前调度并未直接优化“每 token 收益”；token 是完整记账和事后分析的一部分。后续正式论文若提出成本敏感的预算分配，需要把成本明确加入策略并重新实验。

实现只把“质量门槛内、固定行为距离超过阈值”的候选称为一个操作性模式。它不意味着已经识别程序空间全部局部最优点或等效全局最优算法。函数执行采用有界 AST 解释器，候选不能导入库、访问文件或网络、执行循环或反射。当前发现空间是数值评分规则，尚未覆盖任意模型训练管线。

## 实验实际说明了什么

下面比较同一个生成模型 Qwen 下，简单小生境搜索 niche 与加入执行记忆的 relational。两者每次运行均生成 12 个候选，并共享 3 个初始规则。表中是运行均值；TSP/装箱各 5 次，分类各 3 次。

| 指标 | 小生境 niche | 小生境 + 执行记忆 relational | 解释 |
|---|---:|---:|---|
| 分类：独立测试平均错误率 ↓ | 6.85% | 5.49% | 有改善信号，只有 3 次搜索重复 |
| 分类：测试集质量约束模式数 ↑ | 2.33 | 1.00 | 准确率改善没有伴随模式泛化改善 |
| TSP：独立测试最优 gap ↓ | 4.25% | 4.61% | 完整方法没有改善解质量 |
| TSP：重复终端行为比例 ↓ | 81.7% | 48.3% | 能改变重复搜索，但减少重复不等于发现更有用的算法 |
| TSP：验证质量约束模式数 ↑ | 2.80 | 2.00 | 当前完整方法的模式保留更弱 |
| 装箱：独立测试下界 gap ↓ | 12.31% | 12.31% | 最佳规则质量相同 |
| 装箱：验证质量约束模式数 ↑ | 3.00 | 3.60 | 小幅增加，但运行波动很大 |
| TSP / 装箱 / 分类：平均 token 增幅 | 基准 | +30% / +49% / +44% | 相同候选预算下，记忆上下文有明显额外开销 |

TSP 的 gap 使用 Held–Karp 精确最优值；装箱使用不一定可达到的体积下界。分类错误率是三个数据集各自错误率的等权平均。不同任务的损失不可直接求平均。最终程序先在验证集选定，再在固定测试集上评价；测试质量未参与搜索选择。

跨模型结果也有反例：MiniMax 的 TSP 测试 gap 从 niche 的 4.87% 变为 relational 的 7.14%，虽然重复率从 72.2% 降至 33.3%。因此不能把“重复减少”直接解释为“质量和覆盖共同提高”。去掉 W 的消融也呈现任务差异，暂不支持所有任务必须使用 W。

实测报告给出按运行重采样的探索性 bootstrap 区间。这些区间只反映固定数据划分下的搜索波动，不能代表新数据集或新划分的不确定性；3–5 次重复很少，按运行编号配对也不意味着模型使用相同随机数。分类损失差区间虽未跨过 0，仍不足以作确认性显著结论，且未进行多重检验校正。

另做了同 token 上限的已保存轨迹前缀诊断。在该诊断中，完整方法保留的候选更少，质量或模式收益也不稳定。它是事后分析，不能代替重新运行的等 token 预算实验。

这些结果支持三个判断：程序生成闭环能够运行；意图不同但行为汇聚的问题可以观测；执行记忆确实改变搜索决策。**当前不支持“完整方法始终优于简单小生境”或“博士级创新已得到证明”。**

## 与已发表工作的衔接

用户补充的正确 MSLS-MA 文章已重新读取。它在离散空间中维护路径差异、结合局部开发并在停滞后重启，为第六章提供了直接的方法桥梁。当前 TSP 评价统一使用 24 次 2-opt delta 检查；没有将它称作 MSLS-MA 的完整复现，也没有把不同随机路线冒充不同算法。

RMC-CMSA 的起点—终端不一致与 A/W/M 状态，是本次执行记忆原型的主要来源。HDADE 提供分别关注质量与行为分布的原则，本版没有直接加入随机投影。DWD 使用真实参考集，开放程序空间没有这样的参考集，因此当前没有用 DWD 声称真实全局模式召回。逐项源文证据见 [论文衔接说明](THESIS_LINK.md)。

建议第六章标题为：**面向自动算法发现的执行反馈多模态搜索与关系记忆方法**。科学问题收敛为：在质量约束下，如何通过执行反馈识别行为汇聚；何时利用这些关系能以合理成本找到更好或互补的算法规则；何时该机制失效。

[MLEvolve](https://github.com/InternScience/MLEvolve) 已有跨分支引用、长期记忆和 planner/coder 分离；[SeaEvo](https://arxiv.org/abs/2604.24372v2) 已有语义策略簇与互补检索；[AdaEvolve](https://arxiv.org/abs/2602.20133v1) 已有自适应探索和资源分配。上述一般功能不能作为本章独立创新。当前四种主控制器是内部机制对照，未完整复现这些外部框架。

完整章节仍需优先完成：

1. **缩小并核验新增机制。** 针对执行汇聚而设计控制器；先检验简单小生境之外的增量，再决定是否保留 W、增加投影或其他复杂模块。
2. **真正控制总成本。** 预先固定 token/评估预算运行；增加文本策略 novelty 等简单基线，并在统一任务和模型下直接比较 MLEvolve、SeaEvo、AdaEvolve。
3. **检验模式及其用途。** 量化固定 probe 的误拆、误并和测试稳定性；增加具有已知等价类的受控基准，以及存在互补性能或约束需求的任务。
4. **扩大独立验证。** 增加搜索重复、数据划分、任务与预算；先规定主要指标、否证条件和统计方案，再看结果。论文必须报告额外上下文成本与失效情形。

据此，结论是“**具备作为第六章研究原型与初步实验基础的可行性**”。是否形成正式方法章节，要由上述增量和泛化证据决定。

## 使用与复核

直接双击 [dashboard.html](dashboard.html) 即可离线演示，无需模型账号。要发起一次新的真实搜索，在工作区根目录运行：

    python -m chapter6_demo.discovery --task classification --method relational --steps 12 --seed 10 --provider alibaba-token-plan-cn --model qwen3.7-plus --output chapter6_demo/runs/my_classification_demo

此命令使用本机已有 OpenCode 账号。TSP 或装箱只需把任务改为 tsp 或 binpack。要在其他 Python 环境安装依赖，可运行：

    python -m pip install -r chapter6_demo/requirements.txt

全部最终程序的无 API 回放命令：

    python -m chapter6_demo.verify_experiments chapter6_demo/runs/pilot_qwen chapter6_demo/runs/pilot_minimax chapter6_demo/runs/pilot_no_w chapter6_demo/runs/pilot_classification

证据入口：[逐次运行表](results/runs.csv)、[机器可读统计](results/analysis.json)、[回放核验](results/verification.json)、[浏览器核验](results/browser_check.json)、[Qwen 图表](results/qwen3.7-plus_pilot.pdf)。原始结果位于 runs 下四个 pilot 目录，各自 manifest 记录配置和源码指纹；前 62 次运行的冻结核心保存在 artifacts/core_701c32df。早期开发数据不属于正式实验。
