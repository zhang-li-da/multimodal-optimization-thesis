# 第六章研究定位与实验设计修订：智能体探索—开发协同

版本：design-v2.0；日期：2026-09-26（Asia/Shanghai）。依据实现提交 `0da63acf486df508766b3bf33d7d0258644cd04f`，对应 v1.2.3 已完成结果。**本包是研究设计，不是已实现的新控制器、最终预注册或新实验结果。新增模型调用为 0。**

本轮依据用户明确的研究定位修订：第六章研究智能体在广泛决策空间中的探索、方向维护与持续开发；TSP、机器学习工程和数学优化是验证载体。最终只输出一个最佳方案也可以成立。算法集合的集成/路由价值降为可选拓展，不再作为章节成立的必要条件。

## 本轮最重要的修订

| 原先容易造成误解的要求 | 当前设计 |
|---|---|
| 以获得多个行为不同程序概括第六章 | 以外层方向探索、局部开发和反馈资源分配为研究主体 |
| 集合部署收益是章节的必要证据 | 最佳单方案的发现质量、概率、成本效率即可构成主要效果证据 |
| N/F/G/R 足以回答整个问题 | 它们只检验开发池与排序；增加单路径、广泛重启、固定多分支、时间调度、自适应调度 |
| 增大 TSP 城市数就拓宽智能体空间 | 分别操纵任务规模和外层可编辑模块，两类结论分开 |
| 根据固定历史排名推断未生成子代收益 | 固定历史只检查动作；收益用真实续开发与独立测试 |
| 更多分支或更高熵就是更好 | 过程指标需与未来改进和最终效果联合解释 |

## 现在执行什么

先完成任务形态的输出配置校准，再落实方向描述与统一策略接口，做短批次可观测性检查。研究参数在对应批次前冻结。小规模筛查决定下一阶段选择，不允许查看测试成绩后改变当前批次。

本次只提交文档与导航，不改实验源码、原始结果、冻结协议、旧标签或已发布 demo。当前 demo 可继续说明已完成原型，新机制只在后续实现与实验完成后加入。
