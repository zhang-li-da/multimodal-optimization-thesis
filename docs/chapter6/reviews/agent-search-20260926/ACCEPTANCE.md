# 冻结与证据验收

design-v2.0，2026-09-26。以下用于未来批次；勾选表示证据已具备，不预设实验要获得正结果。

## A. 首次模型调用前必须具备

- [ ] 源码提交、干净工作区、任务适配器与方向描述版本；新方法确实实现，非仅文档改名。
- [ ] 最终研究问题、主要对比、效果方向、实际意义阈值与多重比较策略。
- [ ] 所有组的差异表；同一候选语言、模型、初始化、评价、并发、修复和提示信息范围。
- [ ] 数据/任务 manifest、原始内容哈希、开发与确认用途；测试或私有评分不参与搜索。
- [ ] 具体请求上限、token cap 或明确的软预算口径、墙钟、CPU/GPU、程序超时、缓存和后处理规则。尚待 profiling 的数值必须填完才可执行。
- [ ] MiniMax 任务形态校准及独立验收；实际 model ID 和不可变版本可用性。
- [ ] 方向状态、保护额度、续额上限、别名防重置、强制回退、噪声与失败处理全部确定。
- [ ] 随机化任务顺序、搜索种子、重复单位和不完整运行处理。模型不支持 seed 时明确说明，不能承诺相同程序流。
- [ ] 确认实验的样本量/精度依据；探索矩阵只标筛查，不以任意运行次数充当功效证明。
- [ ] 本批次执行预算及停止条件明确，不自动从 pilot 扩为大规模 GPU 运行。

## B. 每次外层行动必须留存

| 字段组 | 最少信息 |
|---|---|
| 身份 | study/task/block/search_seed/model/source/environment/config hashes |
| 动作 | proposal_id、动作 E/D、选择概率、抽样值/可复核 RNG、forced fallback、操作模块 |
| 机会 | 可选方向/父代 IDs、候选质量、剩余额度、方向/谱系/行为 IDs、方向描述版本 |
| 决策依据 | 观察窗口、原始与汇总进展、失败类型、各分数、预定规则和实际选择 |
| 生成 | 提示、原始响应、请求 ID、finish_reason、输出 schema、完整文本/代码身份 |
| 执行 | 内层预算、合法性、逐实例/验证分数、参数种子、资源成本、错误原因 |
| 反馈 | 相对父代/方向最好/全局最好增益、重现分类、准入/暂停/续额及理由 |
| 资源 | 输入/输出/推理 tokens（如有）、未知用量、CPU/GPU 秒、总耗时、缓存状态 |
| 输出 | 当前 validation incumbent、预算时点、最终冻结单方案和独立测试记录 |

不同有效候选数是结果，不是补齐名额。解析/执行失败不免费补位；不确定请求保留停止。checkpoint 恢复应避免重复扣额与重复提交。若未来允许有界修复，所有组同一规则，修复计调用与成本，并作为新版本冻结。

## C. 需要得到哪些实验结果

| 要支持的结论 | 必需证据 | 未得到时怎样写 |
|---|---|---|
| 输出链路可用 | 独立工程用例完整率、截断和成本 | 配置未就绪；不解释机制性能 |
| 方向描述可用 | 冻结规则、盲化结构核验、unknown/敏感性、进展对应 | 仅称谱系/标签分组，不能称可靠区域 |
| 保护产生增量 | 保护开/关的总体预算结果与后续贡献分布 | 仅说明保护能执行 |
| 动态协调有效 | AD−FB/TS 的独立质量或成本增量，动作有实际差别 | 若只过程变了则不声称收益 |
| 反馈信号有效 | 保持信息和成本条件的反馈对应消融 | 不把组合系统优势归给单一信号 |
| 跨任务成立 | 相同逻辑在未见 ML/数学任务的配对表现与边界 | 仅报告已验证任务范围 |

正向研究目标应预先量化，但不能写成“必须实验得出 AD 更好”。失败、无差异、相反方向都完整保留。没有集合部署收益不阻止单方案搜索机制贡献成立。

## D. 统计与冻结后的读出

- 每个任务/块的所有方法及 seed 共同保留；报告每格计划/启动/完成/失败数。
- 候选、实例、API 请求和同一长运行前缀不是独立算法重复。
- 长期曲线所有时点的 incumbent 先按可见验证冻结，再统一离线评价；不能按测试最佳时点选输出。
- 提前终止可以作为 anytime 结果，不冒充达到完整预算。总系统可用性包括基础设施失败；完成配对结果另报且说明缺失机制。
- 无有效方案时的罚分/失败规则在任务协议中明确，不在看到结果后删掉。效果与有效率同时展示。
- 任务尺度/参考值/方向划分随版本保存。近似 TSP 参考允许负 gap；数学数值可行与严格证明分开。
- 标准 MLE 基准成绩和未见任务确认成绩分开；dev 上的成绩不能改名成确认。

## E. 最终章应交付的图表和材料

1. 主要策略的配对结果、实际意义区间和成本。
2. 固定预算质量曲线与达标概率/删失情况。
3. 实际探索/开发及方向资源分配曲线，含强制回退。
4. 保护分支的全体收益/失败与最终祖先贡献，附至少一个负案例。
5. 因子消融、反馈对应、任务规模和模型交互结果。
6. MLE-Bench 官方评分与完整运行清单；数学问题定义和独立检查。
7. 源码、协议、环境、原始日志、只读分析脚本和真实/合成分明的 demo。

## F. 版本顺序

研究设计 PR → 实现 PR → 开发校准 → 最终协议提交 → 数据/环境/源码冻结 → 原始结果提交 → 分析提交 → 独立审阅。历史结果、冻结清单与旧标签不移动；修复后另建批次。当前设计提交不打成“新方法有效”的结果标签。
