# 逐步实验方案：先让机制可检验，再验证长期搜索收益

design-v2.0，2026-09-26。所有下列新增批次均为**待实现、待冻结、未执行**。运行数是分阶段预算建议，不是统计充分性保证；本次不启动任何 API/GPU 任务。历史 v1.2.3 单模型结果单列，不并入新重复。

## 1. 总体路线与主要比较

主线：输出可靠性 → 可观测方向与统一策略接口 → 受控搜索比较 → 保护/反馈消融 → 较大 TSP 与模块空间 → MLE-Bench → 数学优化 → 独立确认。

MLE 接口的工程准备可在 TSP 阶段并行推进；不要求先证明 TSP 所有假设都成立才接 ML。也不让一次 ML 成功掩盖机制对照失败。大规模付费实验须有独立的完整运行协议和预算。

| 阶段 | 候选规模 | 主要交付 | 进入下一阶段的依据 |
|---|---|---|---|
| S0 输出校准 | 最多 84 次请求，见下 | 配置校准和独立验收报告 | 任务形态输出完整，成本可控 |
| S1 可观测性 | 12 次、每次 32 提案 | 全运行状态、机会链和方向审计 | 自然搜索产生可比较的决策状态 |
| S2 搜索策略筛查 | 每种外层空间 40 次；两空间共 80 次 | 五策略质量/成本/过程对比 | 确定可解释的候选机制和强简单基线 |
| S3 归因 | 48 次；反馈打乱可再做 24 次 | 保护×反馈因子对照 | 总体增量可归因，或据负结果收缩机制 |
| S4 MLE 端到端 | 先 6 次接入，再 81 次确认子集 | MLEvolve 配对基线与官方评分 | 新任务上的收益及局限 |
| S5 数学优化 | 先 12 次接入，最终 90 次示例 | 同任务评价、独立证书、成本 | 非 ML 载体的可重复效果 |
| S6 扩展确认 | 按新 pilot 规划 | 全新块/任务、第二模型、长期预算 | 支持最终论文主张及实际意义 |

阶段不是“全跑完才算研究”，也不是自动执行清单。若反馈机制无增量，保留有限保护和简单分配，减少后续臂数；报告原有负结果。

## 2. S0：MiniMax 任务形态输出校准

当前故障主要在 planner，不能把提高输出率当作控制器创新。

### 2.1 用例与调用上限

1. 独立工程用例覆盖从头规划、基于父代修改、带参考方案三种模板；不使用 block 3–10 的 test，也不使用未来正式块。
2. planner 校准：2 个候选配置 × 3 模板 × 3 次重复 = 18 请求。先比较旧上限与一个经服务文档/实际响应确认支持的较高上限；不臆造关闭思考的参数。不同时改提示和上限。
3. coder 校准：同样 18 请求，输入冻结的合法计划，从而独立测量 coder。记录输入长度、最终文本、finish_reason、JSON/schema 合法性、代码执行、延迟和全部 usage。
4. 按预定规则选配置：优先完整率，再在达到目标的配置中选成本低者；不看任务质量。
5. 独立验收：各阶段用新用例 18 请求，共 36。建议门槛 planner 与 coder 各至少 17/18 完整合法；报告 Wilson 区间和具体失败，不能据小样本宣称真实稳定率达到 95%。coder 另报可执行率。
6. 6 个新端到端用例，每个最多 planner+coder 两请求，共不超过 12；建议至少 5/6 完成。总请求上限 18+18+36+12=84。无成功补位或自发继续调参；不通过则诊断并新建校准批次。

保留旧配置作为故障参照，不重复整轮 16 搜索。未知请求不重发。若需要第二模型，只在后续另开小校准批次；近期先用用户选择的 MiniMax M3。

### 2.2 冻结产物

保存 schema、提示模板、模型别名和实际 response model、思考/输出配置、timeout、请求总额和调用上限。服务没有不可变版本则明确未知。校准中的任何额外请求都记成本。

不要改成“直到获得指定数量有效程序”为主预算。所有失败必须消耗共同预算；若研究有效评价预算，则同时给出共同请求/token/时间硬上限，单列为另一估计目标。

## 3. S1：方向和开发机会能否被观察

### 3.1 零模型机制检查

构造：无可用分支、一个分支、两个同收益异方向分支、局部进步未超过全局最好、已知重现、解析失败、容量满、保护耗尽、方向别名、强制回退、预算不足、恢复。每例核对动作与额度；同历史非目标模块相同。对动态调度记录计算概率及固定 RNG 的选择；不要依靠随机恰好同选证明未生效。

`direction_id` 以实际结构为准，不能让重命名变量或 planner 标签建立新区域。按 [研究设计](RESEARCH_DESIGN.md) 做盲化方向描述核验。先检查代表距离/尺度是否有定义，不要求找到真实盆地。

### 3.2 少量真实可观测性搜索

在新开发块上运行 F/R 两个旧分支策略，2 组 × 3 块 × 2 搜索种子 = 12 次，每次 32 提案。共同使用校准配置；这批用于诊断旧 B 规则是否仍限制竞争，尚不声称实现新的广泛探索—开发调度。最多 384 个候选时隙、768 次 planner/coder 请求，不含另外声明的调试请求。

新块编号从 11 起只是命名建议；必须做坐标/实例哈希去重，编号本身不证明独立。协议另设真实 token 与时间硬上限，达到任何上限即停止，保留未满 32 步的结果。具体数值由 S0 成本估计在启动前填入，不能留 null 后声称预算公平。

检查旧 B 在自然生成下的机会链：有效候选 → 竞争性改善 → 非重复 → 入池 → 至少两个仍有额度的分支 → 评分/选择不同 → 后续改善。每组分别给分母和运行分布。

建议诊断目标：每组至少半数运行出现多分支时隙；每组总计至少 10 个多分支时隙；R/G 或 F/R 至少有 5 次实际不同选择。它们是工程可观察性目标，不是入选条件、功效保证或效果通过线。达不到也报告全体质量，不筛除运行。

若输出已可靠而竞争仍不足：分别检查容量、仅在局部改善后准入、立即耗尽额度、8/32 步窗口和质量门槛。只在新协议中改变一个因素；优先为初始竞争方向分配有限启动额度，不通过放宽到任意低质量程序人为制造竞争。

可另构造有两个可用真实程序的共同 checkpoint，给每种策略等额 4–8 步真实续开发。程序从开发集选取，选择规则预先冻结。它估计“已有竞争方向条件下”的调度效果，不能混作自然端到端表现。固定历史重放不包含这些未生成子代。

## 4. S2：扩大外层空间并比较五种搜索策略

### 4.1 先区分两个实验因素

**TSP 规模**与**智能体可修改内容**分开操纵：

| 外层空间 | 可以修改 | 不能据此声称什么 |
|---|---|---|
| P：受限规则 | `priority(f)`，公共构造和局部搜索固定 | 不能声称已覆盖算法模块级开放空间 |
| M：模块化算法 | 构造规则、候选边策略、局部改进算子、重启/扰动模块 | 模块接口仍有限，不是任意程序空间 |

M 采用固定任务适配器：输入实例、算法随机种子、执行预算；输出合法路线与执行日志。每次内层运行限制距离计算/候选移动评价次数和墙钟时间，超限停机、无效解罚分。所有策略可用相同模块、依赖和公共种子。先完成可运行性与成本检查，再冻结任务适配器。

同策略跨 P/M 的绝对结果只能反映不同可用空间，不单独归因于搜索机制；主要比较在每个空间内部进行。不要同时扩大模型能力和可用算子后只与旧 v1.2.3 比较。

### 4.2 五种主策略

| 代号 | 规则 | 用途 |
|---|---|---|
| SP 单路径 | 初始化后只改当前最佳的一条路径；无持续多方向保护 | 偏开发基线 |
| WR 广泛重启 | 每步独立提出方向，不利用生成候选继续开发；共享任务定义和初始种子 | 偏探索基线 |
| FB 固定多方向 | K=4，探索/开发固定 1:1，方向保护规则相同，简单收益次序 | 强简单多分支基线 |
| TS 时间调度 | 与 FB 共用方向/保护/排序，仅将开发概率随消耗预算从 0.2 线性升至 0.8 | 排除只需预定从探索转开发 |
| AD 反馈调度 | 与 FB 完全相同，仅按已观察进展改变探索/开发概率 | 候选核心机制 |

TS 是简化时间调度，不能冒称完整 MLEvolve。SP/WR 的区别包含预期的历史选择差异，但不改变模型、修复工具、可编辑语言、评价器或隐藏资源。共同初始候选费用全部计入。

先在每种空间做 5 策略 × 4 个新开发块 × 2 种子 = 40 次；P/M 共 80 次。每次最多 32 提案，并施加相同、预先冻结的 token/时间上限。共 2,560 个时隙、最多 5,120 次两阶段请求。若不同预算时限会改变 TS 决策，不能把一个 32 步运行的 8/16 步前缀称为独立的短预算策略运行。

主比较先指定 AD−FB；AD−TS 是辨别反馈必要性的关键次比较；SP/WR 用于解释探索与开发两端。小矩阵只能筛查，不能通过事后选择最弱基线建立优势。

### 4.3 TSP 数据与大规模评价

14 城市保留为回归与机制单元，不继续承担主要泛化结论。开发用 n=50、100，独立同分布测试也使用这两档；n=200 为冻结程序外推，n=500 作为成本允许时的压力测试。每块建议每个开发规模 probe/validation/test=12/36/60，三生成族均分；外推每规模 60 个独立实例。正式实例数在评价耗时 profiling 后冻结。

当前 `optimum_tsp` 使用 Held–Karp，不能直接给它输入 50/100/200 城市。先将实例生成、参考值计算和候选评价拆开，对旧精确评价入口加规模保护。参考解离线保存；精确值须有求解状态/证书，近似值则明确算法、预算与 best-known 来源。

一般报告有符号 `100*(L-L_ref)/L_ref`，称相对参考解差距；只有证明最优时才称最优 gap。若候选优于近似参考，负值要保留，不能沿用旧评价 `max(0,...)` 截断。参考解不暴露给生成模型。

P 中内层公共 2-opt 预算按规模确定并对所有组一致；先在开发实例比较固定 24 次与一个按 n 增长的预算（例如 10n 次候选移动检查），然后冻结一个主配置，另一个只作敏感性。主结果同时给局部搜索前后质量，避免公共后处理掩盖构造差异。M 用共同执行上限，不给某策略额外内层优化。

每实例 CPU/墙钟上限在指定硬件 profiling 后冻结；线程、依赖、种子、并发和缓存共享规则一致。离线参考成本单列；搜索过程中反复执行候选的成本必须计入。

## 5. S3：把整体优势拆成可解释机制

### 5.1 保护×反馈的 2×2 因子

共同方向描述、准入、候选生成、容量和 B 内排序，改变两项：固定/反馈分配；有限保护开/关。无保护组使用相同质量合格条件，但不保证两次机会，按同一即时优先级分配；不是禁止局部开发。先写清自然后果，不能同时改准入和记忆。

4 组 × 6 新块 × 2 种子 = 48 次，建议使用通过 S2 的 M 空间和统一预算。预先指定保护主效应、反馈主效应和交互中哪一项是主要假设，报告全部四格和配对差值。

若要声称“正确进展证据”重要，再做 AD 与 AD-shuffled：仅将调度器读取的历史进展对应在可比方向间打乱，实际候选质量、准入、提示和总预算不改。2 组 × 6 块 × 2 种子 = 24 次候选专项。保留全局输出可靠性信号，避免仅通过破坏错误恢复制造劣势。

N/F/G/R 作为旧机制的专项消融仍可保留，但不是本轮五策略主线的替代：N/F 检验显式开发池；F/G/R 检验开发池内排序。只有准备继续主张 q(tag) 的贡献时才为 G/R 安排真实新运行。

### 5.2 潜力分支的归因

记录一条分支在获得保护时是否未超过全局最好；其后是否改善方向最好、刷新全局最好或成为最终输出祖先。用“所有满足条件的机会”作分母，终止前没有足够观察窗口的分支标为右删失。

后验成功谱系只说明关联；保护开/关实验才支持干预效果。不能只展示成功链，也不能把共享祖先的多个后代作为独立重复。共同 checkpoint 的随机分配续开发可作补充，但其结论限定于该 checkpoint 分布。

## 6. S4：MLEvolve 同类机器学习工程实验

具体来源和已核对入口见 [对齐核查](BENCHMARK_ALIGNMENT.md)。当前项目尚未接入 MLE-Bench，以下不是现有 CLI 可直接运行的任务。

### 6.1 接入与环境

1. 固定 MLEvolve、MLE-Bench、镜像和依赖版本，准备已接受相应数据规则的任务。只向智能体挂载 public 数据与描述；私有标签、官方评分代码/结果由独立评估进程管理。
2. 所有方法在同一 GPU 类型、显存、CPU、RAM、线程和最大并发下运行。自由代码必须在隔离容器中执行；不能沿用只适合受限 `priority(f)` 的解释器边界。任务数据与最终评分权限分离，网络/预训练模型可用性事先固定且两组相同。
3. 复用统一 planner/coder、内层验证和提交格式，记录完整有效的 pipeline、首次合法提交时间、训练资源、调试和错误处理。
4. 使用官方 dev 列表中的三个候选：spaceship-titanic、movie-review-sentiment-analysis-kernels-only、plant-seedlings-classification。它们是开发任务，不再作独立确认数据。官方已列出 invasive-species-monitoring 的准备压缩包内容缺失问题，本设计在执行前选择另一图像任务，避免把已知数据故障混入机制检查。不得因我方得分低临时更换；若数据或环境不可用，按预先规则记录并修订新协议。
5. 接入 pilot：我方与 MLEvolve 同模型适配版 × 3 任务 × 1 种子 × 2 小时 = 6 次，上限 12 单 GPU 小时。这只验收链路与资源行为，不能根据 2h 下未触发的长期机制判 MLEvolve 无效。

### 6.2 两种实验轨道

- **机制轨道：** 在相同执行/生成框架中仅替换方向与调度模块；冷启动、记忆内容、编码模式和修复预算相同。用于因果归因。若使用 MLEvolve 框架承载，明确标注派生版本与保留模块。
- **系统轨道：** 我方完整系统与固定提交的 MLEvolve 比较；同骨干模型、任务、硬件、时间和调用计费。使用 MiniMax 时称“同模型适配比较”，不是原论文 Gemini 配置精确复现。

系统轨道最终至少有 MLEvolve 和最强简单基线。主输出为预定 validation 规则选出的单 pipeline；集成不是我方章节成立的前提。若比较作者系统默认提交策略，保留其后处理并对双方采用一致的总时间计费与信息限制，另报单方案/后处理两种读出。不能仅删除对方集成然后直接对标其论文数字。

### 6.3 分阶段范围和预算

冻结 9 个未用于调参的任务，low/medium/high 各 3 个，按元数据与预定随机种子抽样，不按我方得分选任务。它不是未经核对的“作者同一个 9 任务子集”。3 系统 × 9 任务 × 3 种子 × 12h = 81 次，上限 **972 单 GPU 小时**，资源不足时先做开发预算估计，不隐去硬件差异。

最终对齐全基准的预算例：2 系统 × 75 任务 × 3 种子 × 12h = 450 次、**5,400 单 GPU 小时**；加入第三基线为 8,100。准备、官方离线评分、镜像/缓存、LLM 费用另外列账。可先发表预注册子集结果，但不将它表述成完整 75 任务复现。

凡已用于调参/看反馈的官方 dev 或 pilot 任务，在全 75 结果中标出；全量是基准覆盖成绩，独立确认应单独报告未见任务部分。若已看过 9 个确认任务再修改方法，这 9 个也转为开发证据。按新的未见任务重新确认。

### 6.4 必需结果

官方 valid、medal、gold、above-median、任务原始分数；分层汇总与全部任务×种子结果；预算分位点上的冻结 incumbent；LLM tokens、GPU/CPU 时间、首次有效提交、方向投入与保护贡献。最终成绩使用官方私有评分一次性读出。绘制后验隐藏测试曲线时，所有时点 incumbent 必须先在搜索中冻结，离线评分不得反馈给智能体或用于挑选最佳时点。

## 7. S5：数学优化任务作为不同结构的载体

目标是检验方向与资源机制，不是把函数值不同直接称作算法模式。优先对齐 MLEvolve 表中的几何构造、加性组合、自相关/不等式三类。已检查的公开仓库没有找到独立的 15 任务可执行套件；必须先取得并核对原始定义、维度、可行性验证器、初始构造和评价预算。

先选每类 1 个开发任务，例如方形圆堆积、sums-differences 和一项自相关问题，**名称仅作接入候选，不能替代完整数学定义**。若只能自建变体，明确标为变体，不沿用作者成绩作直接对比。

1. 用公开已知可行解和故意违规解验证评价器；区分浮点可行、高精度复核、严格证书。
2. 全组可修改相同参数化、构造、搜索算子；初值与内部求解器预算一致。方向按这些实际选择描述，内层优化轨迹另存。
3. pilot：2 系统 × 3 开发任务 × 2 种子 × 2h = 12 次、24 运行小时。任务需要 GPU 时另计 GPU 资源，不能默认等同 ML 成本。
4. 接入完成且定义对齐后，15 任务 × 2 系统 × 3 种子 = 90 次作为预算例。若选择 12h/次则上限 1,080 运行小时；该时限是本方案的待冻结选择，不声称已核实为作者数学任务的逐项时限。
5. 对用于 pilot 的任务单列开发成绩；余下任务或预注册的未见参数实例承担确认。不得按结果挑选有利任务。

主要结果是可行性、冻结最终目标值、达标时间及独立验证；整数/离散构造给完整对象和检查，连续构造给高精度误差界。单个数学构造通常没有 ML 意义的 train/test，使用未见任务/参数实例和独立验证器，不能虚构测试集；数值改善不自动成为严格数学定理。

## 8. 指标与统计：效果是主要证据，过程用于解释

### 8.1 主要与次要指标

- 主效果：共同预算下由可见 validation 选出的单方案独立成绩。任务方向统一后作配对差；异质量纲不直接平均。
- 效率：冻结预算点的质量曲线、达到预注册阈值的成本/概率。未达到阈值按删失处理，不只平均成功运行。
- 过程：资源投入份额、滚动熵、有效方向数、停滞后的切换、多分支选择机会、局部成功链和保护后的全局贡献。
- 成本：全部请求和失败、推理/输入/输出 tokens（可得则分项）、方向识别/记忆调用、程序执行、调试、GPU 小时、最终推理/后处理。

对于固定窗口内的方向资源份额 p_k，可报告 H=-Σp_k log p_k、exp(H) 及最大份额。按提案数和按实际成本分别计算；方向数变化时同时列 K/unknown，必要时给 H/log(K)，K≤1 单独定义。早期集中可预注册为前 25% 预算中单方向份额>0.8，但这是操作性诊断，不是普适坏现象。只有结合后续独立效果才称有害集中。

方向的“未来有收益”只能用于离线解释，不能回流在线准入。对照策略可以不拥有多个可选方向；可观测性门槛只约束本应比较多方向的处理，不据此删除 SP/WR。

### 8.2 实验单位与不确定性

TSP 以独立实例块为外层单位，搜索 seed 为块内重复；ML 以任务为外层、seed 为内部；数学以任务/参数实例为外层。配对重采样时保留所有方法与种子的对应，不把候选、路线或 API 调用当独立实验。

报告全部配对、均值/中位数、区间、达标比例和失败。确认阶段先定一个主要比较与实际意义阈值 δ；多项主要检验用预先指定的 Holm 等控制。样本量用新版 pilot 的块/任务级差异作精度或功效规划，旧“排序没改变动作”的差值不能作为新机制效应估计。

定义差值为我方损失减基线；95% 区间低于 0 支持方向，低于 −δ 更有力支持达到实际收益；跨越有利与无利范围时结论不确定。非显著不是等价；若目标是同质量少成本，需预先定义非劣界。

### 8.3 预算计费与测试纪律

确认主轨道使用统一墙钟/硬件，辅以同 token/评价预算的消融。硬 token cap 须在请求前按输入与最大输出预留额度，不够则停止；服务无法提供上界时称软预算并公开越界，不能伪称硬 cap。真实服务异常和 usage 不明保留为未知，不能计零。

共同种子/预训练缓存的冷启动成本与 warm-cache 规则一致。跨任务经验默认重置；若研究跨任务记忆，应另立按顺序/迁移对照。公开基准可能存在模型预训练污染，报告版本与可见信息，不能声称仅靠本地隔离即可排除预训练污染。

## 9. 结果如何决定下一版

| 观察 | 科学解释与行动 |
|---|---|
| 输出仍频繁失败 | 先解决任务接口；不能归因于探索策略 |
| 输出可靠却无多方向竞争 | 检查空间、准入和额度时序；该配置无法识别排序效果 |
| AD 改变动作但不胜 FB/TS | 反馈复杂度未获支持，优先采用简单策略 |
| 保护有效，族排序无增量 | 以有限开发保护为重点，移除多余关系主张 |
| 熵/方向数变化但性能无变化 | 仅支持过程变化，不支持效率提升 |
| 小 TSP 有效，ML 无效 | 报告任务边界，诊断变成本和验证噪声，不直接宣称通用 |
| 最终单方案提升、集合部署无收益 | 核心主张仍可成立，集合实验不是验收门槛 |
| 全部合理对照均无收益 | 保留系统和负结果，重新审视机制差异；不能用 demo 代替方法贡献 |
