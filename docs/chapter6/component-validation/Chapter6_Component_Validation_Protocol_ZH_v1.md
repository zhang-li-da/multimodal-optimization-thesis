# 第六章组件验证协议 v1

本协议对应分支 `experiment/chapter6-component-validation-e0-e2-20260927`，使用本机 OpenCode 的 `minimax-cn-coding-plan / MiniMax-M3`。S3 r3 的源码、结果和标签保持不变；本协议产生独立的数据快照、运行目录、测试结果和报告。模型调用只在协议冻结、预检通过后开始。

## 研究对象与边界

本阶段拆开四个候选组件中的前两个保护因素：方向信息仍由固定 probe 行为描述产生，方向档案与开发投资池分开；P-S 表示开发机会的期限优先保障，P-E 表示有未兑现额度的条目不能被淘汰。E0 修复账本与入口，E1 比较同状态的机会成本，E2 做 P-S × P-E 的 2×2 归因。

E0—E2 是组件筛查，不是最终确认性研究，也不声称跨任务、跨模型或普遍优于简单基线。模型服务没有不可变版本时，报告保留请求模型、响应 `model`、端点类型和时间，并将服务版本标为未知。

## E0 实现修复

有效候选可以被记录为方向，但只有一次性新方向试用或明确的方向内局部进展才获得开发额度。行为变化不会重置同一谱系累计额度。零额度方向不进入活动池，不触发淘汰；续期不能超过谱系上限或剩余预算窗口。调用次数、完整响应、有效程序、相对父代改善、全局改善、token、执行成本、未成熟和删失试用分别记录。

E0 通过离线单元测试和固定合成历史验收，不使用 test 结果调参。验收失败时停止实时实验，不补跑 S3。

## E1 同状态真实分叉

E1 计划使用四个新数据块（44—47）和八个在延续结果读取前冻结的共同检查点。每个检查点包含全局最好程序、至少一个质量稍落后且行为不同的候选及其完整历史。三种延续为：`C-I` 继续当前最好、`C-B` 开发落后方向、`C-E` 无父代探索；每种两次重复，每次四个提案，共 `8 × 3 × 2 × 4 = 192` 个延续提案。

主要终点是相对检查点全局最好损失的改善，机会成本比较为同状态下 `C-B - C-I`。同时报告相对父代改善、首次超过检查点最好所需步骤、完整响应、实际 token 与评价成本。未完成观察窗口的试用记为未成熟/删失，不按零收益处理。八个检查点是诊断抽样单位，不当作八个独立数据块。

## E2 保护机制归因

E2 使用新数据块 40—43、两个搜索种子和四个处理组，共 32 次搜索。所有组共享相同槽位表和总预算：20 个当前最佳开发槽位、6 个无父代探索槽位、6 个分支开发槽位；活动池容量为 2，新方向一次试用，局部进展一次续期，谱系上限为 4 个槽位。

| 组 | P-S 调度优先 | P-E 防淘汰 |
|---|---:|---:|
| P00 | 关 | 关 |
| P10 | 开 | 关 |
| P01 | 关 | 开 |
| P11 | 开 | 开 |

普通分支槽位按验证质量选择；P-S 只改变分支槽位内的期限优先调度，P-E 只改变仍有未兑现额度条目的淘汰资格。四组的准入、候选提示、槽位数、模型输出上限和失败处理完全相同。无效或截断输出消耗对应槽位；供应商或未知传输失败只终止该任务，禁止自动重试或替换。

主要终点是 validation 选择的单程序 Test gap。机制链记录：方向保存、获得试用、分支选择、零额度替换、额度兑现、父代/全局改善和成本。按完整数据块做描述性配对差值和 bootstrap；不把 API 请求、候选或 test 实例当作独立重复，不报告确认性 p 值。

预注册筛查阈值为至少 0.3 个百分点的实际改善且平均 token 增幅不超过 10%。区间同时允许收益与损失时标为证据不足；若只一个因素有独立信号，最终只保留该因素；若没有增量，删除或简化保护机制。不会为保住预设架构而调参或追加任务。

## 数据、测试与版本管理

搜索只加载显式 probe/validation 快照。所有搜索终态后才开启 test；每个 test 绑定冻结的 validation readout 和独立 test 快照。新块与历史块进行 ID 和精确坐标内容去重，几何等价不宣称已验证。报告包含失败任务、未知成本、截断、未成熟试用和归档哈希。

提交顺序为：E0 源码与协议测试 → 冻结 manifest → 预检 → E1/E2 搜索 → test → 离线分析与归档 → 独立提交和 GitHub 草稿 PR。任何阶段停止都保留已经发生的响应和成本，不覆盖历史结果。
