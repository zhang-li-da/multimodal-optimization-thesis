# 同状态短程机会成本实验草案

这份草案定义下一轮不改变自然搜索主实验的诊断批次。它只回答一个条件问题：在同一个已经冻结的搜索状态下，四个后续提案应继续当前最好程序、继续一个落后但行为不同的分支，还是先探索一个新方向并继续开发它。

## 冻结矩阵

使用全新的 TSP 数据块 52--59。每个新区块对应 S3 的一个不可变 `FB_P` 历史运行（32--39），在该历史前缀上建立两个检查点：第 8 步 `early`，第 24 步 `late`。检查点的程序重新在对应新区块的 probe/validation 上评价，不能使用 test，也不能看到后续响应。这样共有 16 个检查点。

每个检查点运行三种动作，每种动作两个重复。每个任务固定四个提案，最多八次模型请求（每步 planner + coder），共 96 个任务、384 个提案和 768 次请求。重复属于同一检查点的随机重复，区块才是主要分析单位；早晚两个检查点在同一块内配对，不能当成两个独立数据块。

若固定前缀没有满足质量接近且行为不同条件的候选，必须记录 `preparation_incomplete`，不能用后续节点或结果导出的候选替换它。建议固定条件为：候选验证损失严格高于 incumbent、差距不超过 0.035，probe 行为距离大于 0.08。

## 三种动作

`C-I` 从检查点 incumbent 开发。后续父代是这个投资项目中最近一次有效局部改进的子代；全局 incumbent 单独维护。

`C-B` 从冻结的落后分支开始开发。分支跨越行为单元时仍继承同一个 `investment_id`，不能因行为分类变化重新领取预算。每次续开发同时记录相对项目历史最好值和相对父代的收益。

`C-E` 只在第 0 步进行无父代探索；第 0 步得到有效候选后，第 1--3 步开发该探索结果及其局部改进子代。如果第 0 步无效，后续步骤继续记录为 parentless exploration，不能伪造父代，也不能把失败探索算作已完成开发单元。

这要求新增的状态机同时保存 `behavior_cell_id`、稳定的 `investment_id` 和不可变 `lineage_id`。行为改变只是诊断信息；项目续期依据项目历史最好结果、成本和剩余窗口，不能自动重置预算。

## 结果与隔离

主要终点是四个提案后按 validation 选择的程序在独立 test 上相对检查点 incumbent 的改善。必须同时报告相对父代改善、首次全局改善步、探索转开发比例、有效/截断比例、实际 token、耗时和动作轨迹。只有当 `C-B` 或 `C-E` 在相同检查点和相同成本下超过 `C-I`，才可称为机会成本上的条件信号；“分支曾经局部改善”本身不是方法增益。

准备阶段只保存 probe/validation 快照和检查点。所有任务终止后才读取 test。服务失败不重试；全局限流暂停后，未启动任务保持 `not_started`，不能逐个撞同一错误。测试和分析脚本应保留不完整任务，不用默认失败值制造比较结果。

## 需要新增的入口

1. `short_horizon.py`：离线检查 52--59 与历史数据无重叠，重新评价固定前缀，并生成早/晚 16 个检查点及其哈希。
2. `short_horizon_runner.py`：复用 E1 的持久化和诊断调用，但实现 `ShortHorizonState`。特别覆盖 `C-E` 第一步探索、后续开发、无效探索和断点恢复。
3. `study_short_horizon.py`：实现 `prepare`、`verify`、`freeze`、`search-all`、`test-all`，任务矩阵必须由冻结 manifest 重建，不能在运行时追加。
4. `test_short_horizon.py`：至少覆盖检查点选择不读 test、三种动作父代序列、跨行为单元的项目连续性、无效探索不造父代、请求/提案计数和 provider halt。
5. 分析脚本：按区块汇总早/晚配对差值，单独报告准备失败和基础设施失败；不要把重复任务当作独立区块。

## 主要风险

- 历史 S3 前缀在新块上可能没有合格分支，准备失败是数据事实，不应补抽。
- `C-E` 可能没有产生有效探索根，必须保留“未开始后续开发”的删失状态。
- validation 进步转为 test 进步可能失败，不能用局部收益替代独立测试终点。
- 早/晚检查点共享同一块和历史模型轨迹，区块聚类与成本配对必须保留。
- 这是机会成本诊断，不是最终确认实验；即使得到条件信号，也不能直接宣称完整第六章方法成立。
