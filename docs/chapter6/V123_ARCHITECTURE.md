# 第六章 v1.2.3：冻结搜索与可复核证据

本版沿用 v1.2.1 控制器和 v1.2.2 搜索运行器，新增单模型配对实验的准备、调度、离线分析和演示。方法代码来自 44bafd2；本轮不是一个重新命名的全新控制算法。独立评审原文保留在 [v1.2.2 评审](reviews/v122/THESIS_READINESS.md)。

## 1. 研究对象与章节定位

研究对象是受限 Python 规则 priority(f)，它在多个 TSP 实例上决定下一城市的构造优先级。一次外层搜索修改程序；程序的内层执行才产生具体路线。本轮限定 14 城市、三类几何分布、固定 24 次确定性 2-opt 检查。最优路线长度用于计算评价 gap，不提供给模型或候选规则。

这里的多模态指质量合格、执行行为不同的程序模式，不指图像、文本等输入模态。程序文本不同、策略标签不同、单个实例路线不同，均不能单独证明两个真实算法模式不同。有限 probe 上的边集距离是一种操作性描述；有限验证向量相同也不证明两个程序在所有未来实例上等价。

暂定研究题目为《面向自动算法发现的质量保护多模态搜索与有限分支开发方法》。当前可写问题定义、原型、历史失败分析和验证路线；关系排序的性能贡献、关系信息的独立贡献、集合用途须分别举证。

## 2. A/B/M 的职责与执行顺序

~~~mermaid
flowchart LR
    X[冻结 probe / validation] --> E[受限程序执行与评价]
    I[三条共同手写规则] --> A[A: 输出行为代表]
    A --> S[共享 niche 普通调度]
    B[B: 最多 3 条分支 / 每条 2 次机会] --> S
    M[M: 已执行反馈] --> Q[族频率与局部收益评分]
    Q --> S
    S --> P[Planner: 修改计划]
    P --> C[Coder: 受限规则]
    C --> E
    E --> A
    E --> B
    E --> M
    E --> F[搜索结束后按 validation 冻结程序]
    F --> T[全部搜索结束后独立 test]
~~~

- **A 输出档案**：保存质量门槛内的有限行为代表，普通调度可从中选父代。最终统一读出还会从全部有效候选重建档案，保证不同方法使用相同输出规则。主质量指标来自 validation 最佳单程序。
- **B 开发池**：保存相对父代有实质进步、准入时质量合格、且不只是重现已知规则的候选。B 独立于 A，因此 A 的行为去重不会直接剥夺 B 的后续机会。
- **M 执行反馈**：记录分配标签、父代、结果和分类。族评分使用已执行候选的标签统计；这不是完整条件转移图，也不是校准后的成功概率。
- **W**：本版本不参与父代、参考或排序。节点中仍保留内层轨迹作为诊断数据；这不等于启用了轨迹记忆调度。

准入判断优先级是非法 → 已知规则重现 → 质量不足 → 合格父代进步 → 其余有效候选。已知重现要求 probe 行为和 validation 逐实例损失都与某个旧有效规则完全相同。实质父代进步阈值为 gap 1e-4，准入质量容差为当时全局最佳 gap + 0.035；行为碰撞半径为 0.08。

每个被保留的 B 条目得到 2 次续开发机会；奇数提案步允许开发，偶数步走共享普通调度。真实发出并完成处理的非法候选也扣除一次机会。额度耗尽或容量淘汰会结束该条目的开发。容量淘汰优先考虑耗尽条目，再依据 gain/(1+attempts)；重新找到已知规则不能更新额度。已入池条目不会因后来全局最佳变好而重新被质量门槛剔除，但额度、容量与总提案预算仍有限。

成功深度只沿成功准入的改进链增加；尝试深度是在被开发父代的成功深度上加一。失败尝试不能增加成功深度。身份、配额、源码、选择和事件均可重放核验。

## 3. 本轮唯一策略差异

两组共享初始化、普通 niche 调度、提示序列化、W 关闭、准入、淘汰、容量、预算和测试规则。只有开发时隙的 B 父代选择不同：

| 策略 | B 内选择 |
|---|---|
| F：niche_fixed_dev | 按 created_order 选择最老仍有额度的条目，直到耗尽；严格 FIFO |
| R：relational_branch | 最大化 q(tag)+0.25*gain/(1+attempts)；同分按创建次序、节点 ID |

q 在某标签已有至少 2 次候选观察时，取 (1+合格局部改进数)/(2+观察数)；否则回退到全部候选的平滑统计。非法候选、已知重现都计为没有新增合格进步。标签代表控制器要求尝试的方向，不是已验证的实际程序语义。

相同历史下，非开发时隙决策及提示相同；不同真实运行中，模型随机输出会逐步造成不同历史。因此平均表现的差异不能自动被解释为族信息的因果贡献。仅收益排序 G 在本轮只计算同一状态下的反事实父代，不执行其后续模型调用。

当前运行器正式接入的是 F/R 两组。无 B、仅收益 G 的真实搜索入口，以及打乱族信息实验仍未在本轮实现或执行。不能把四组方案文档称作已有四组证据。

## 4. 冻结、运行和回放分层

| 层 | 主要文件 | 对结果的作用 |
|---|---|---|
| 既有算法与评价 | demo/v12_1_controller.py、benchmarks.py、discovery.py | 本批次全程不改 |
| 既有耐久运行器 | v12_2/runner.py、calls.py、test_stage.py | 持久化请求、恢复、冻结程序、测试隔离 |
| 本轮任务调度 | v12_3/study.py、protocol.final.json | 绑定协议与 16 项顺序；连续基础设施失败时停止 |
| 分析 | v12_3/analyze.py、verify_readout.py、plot_results.py | 汇总所有计划项、区块配对、评分尺度与重放；零模型调用 |
| 交付 | v12_3/package.py、build_demo.py、browser_check.py | 逐成员哈希、离线回放、浏览器核验 |

冻结清单同时绑定旧运行源码、新调度文件、模型别名、环境和实例坐标。本轮单独修订为 MiniMax M3 × F/R × 区块 3–10＝16 次；原双模型草案保持原样。研究单位是 8 个配对数据区块，不是 864 个实例或数百次 API 请求。token 成本实测，同提案预算不写成同 token 预算。

请求发出前落盘；原响应落盘后才解析。不可确定是否完成的请求不自动重发。解析失败占用提案时隙，不补位。全部搜索终结后才启动独立 test 进程。源码、任务、实例、原始响应、选择、额度、结果及失败都形成可追溯关系。

实时运行严格核对冻结环境；离线分析和程序复核记录当前环境，允许在另一台电脑核验。逐实例路径、离散输出和程序身份要求一致；数值比较使用既有绝对 1e-12、相对 1e-10 容差。另机运行结果须另存，不能覆盖首次实验记录。

具体关联材料仍在原 papers/、论文总报告和历史实验包中；本轮不重复改写已发表工作的贡献。外部 MLEvolve、SeaEvo、AdaEvolve 等已有记忆和调度研究，不能把这些通用系统组件本身宣称为本章原创。当前值得检验的增量是：有限执行证据下区分重现与可开发进步，并将后者兑现为有预算的分支开发。

下一步应依据本轮 [结果报告](../../experiments/chapter6/v12_3/results/minimax-20260926-r1/REPORT_ZH.md) 决定。先解决实际阻塞机制触发的问题；再在统一普通调度下做 N/F/G/R 归因。算法集合价值应在冻结程序上，用独立训练和冻结的选择器，与初始规则集合、最佳单程序、同容量 top-K 质量集合比较。Oracle 只能是潜力上界。
