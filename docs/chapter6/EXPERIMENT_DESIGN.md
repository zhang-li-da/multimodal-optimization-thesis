# 第六章完整实验设计

**本文件是可执行的分阶段研究设计，不预设完整方法一定有效。** 已运行与计划实验分开登记；旧 pilot、冻结追加验证、下一版机制开发和最终检验不得混为同一数据池。

## 1. 核心主张与否证对应

| 主张 | 最小实验 | 主要证据 | 否证或缩小主张的条件 |
|---|---|---|---|
| 有限 probe 会误判程序关系 | 已知等价类的受控语言 + 独立 witness | 错误合并、错误分离、未决率、执行成本 | 误判极少或简单扩大固定 probe 就同样有效 |
| 意图/父代/操作到终端的条件关系有预测价值 | 历史关系预测下一次终端/有效增益；时间外验证 | 校准误差、对数损失、增量预测与决策效果 | 仅质量、标签计数或代码相似度能达到相同效果 |
| 关系记忆改善固定成本搜索 | 与 niche/质量 UCB/打乱图/文本新颖性比较 | 独立测试质量或有用模式的增益，另一指标非劣 | 优势仅来自更多调用、额外上下文或不公平质量门槛 |
| W 有独立作用 | 删除 W、打乱 W、随机前缀、真实轨迹 | 条件预测增量 + 搜索消融 | 终端和父代已解释全部收益，或作用只来自 token 变多 |
| 新方法区别于最近邻 | MLEvolve、SeaEvo、AdaEvolve、FunSearch式分簇/GEPA适用对照 | 统一接口、版本明确、相同成本的增量 | 强基线与简单扩展已达到同样效果 |

主结论不能只用“重复更少”。重复既可能是必要局部开发，也可能是 probe 看不到的质量改进。必须区分有质量收益的相似候选与无收益重复。

## 2. 当前已落实的冻结验证

| 项目 | 固定设置 |
|---|---|
| 对照 | 原版 niche vs 原版 relational，搜索机制和提示不修改 |
| 模型 | Qwen3.7-Plus、MiniMax-M3 |
| 任务 | TSP、在线装箱、3 个数据集上的分类规则发现 |
| 独立块 | 每类任务 10 个新随机划分/实例集；同一块两方法配对 |

| 预算 | 每次 60,000 输入+输出 token 硬上限，候选安全上限 60 |
| 测试 | TSP/装箱每分布 16 个新测试实例；分类四分区，所有统计特征仅 fit 拟合 |

| 修订 | MiniMax 高并发限流后全提供方批次在低并发下重跑；旧批次全部保留，费用单列 |

此阶段回答原组合是否值得进入更昂贵的框架比较。若它连简单 niche 的稳定增量都没有建立，不应跳过该结果直接扩大基线矩阵或预设下一阶段成功。

## 3. 实验数据的四层隔离

1. **方法开发任务集 D_dev：** 可用于改提示、阈值、关系表示和超参数。不进入主结果。
2. **搜索内部数据：** 拟合训练集、快速 search-probe 和选择验证集。所有方法具有相同权限与预算。
3. **新 witness 数据：** 只供拟议关系辨识器按登记规则消耗；其抽样、标签权限与成本对所有需要它的对照一致。不能从最终 test 取样。
4. **最终 audit/test：** 搜索与方法冻结后一次性评价。拟合预处理、自动选择、阈值设定和程序修复均不得使用这里的反馈。

对于跨任务算法发现，应另有完全未参与设计和搜索的任务/数据集。只更换同一数据集的随机划分不能证明跨数据集泛化。公共小数据可能已出现在模型预训练中，应增加生成型任务和较新的公开任务，并把记忆性限制写入论文。

## 4. 受控机制基准

### 4.1 已知等价与差异的规则空间

使用有限离散输入域与有界语法，例如 16–32 种状态、4–8 种动作、可枚举的算术/条件规则。枚举每个合法程序在整个输入域的行为向量，并按严格行为等价去重，得到有限域内可确认的真实类别。

用独立随机生成的目标函数/实例分布定义质量；挑选质量合格类别须在算法运行前固定。设置多个质量相近而行为不同的正确类别，并包括质量差的远距离类别，防止 novelty 一项即可取胜。若研究局部盆地，需额外定义可枚举变异邻接和确定改进算子，公布实际盆地数。

系统改变以下因素：

- 等价改写数量与语法冗余倍率：1、4、16；
- 模式频率不平衡：均匀、1:5、1:20；
- 稀有分歧状态概率：0.01、0.05、0.20；
- 起始策略到终端模式的汇聚强度：低、中、高，由固定转移核产生；
- 质量噪声：无噪声与两个固定方差水平；
- 动态分布：单独的漂移组，不与平稳理论混用。

完整笛卡尔积过大时，预先选正交子集，公开配置；不能看结果后只保留有利角落。先用小规模全枚举确认机制，再用真实 LLM 生成测试其外部有效性。由人为转移核产生的实验只能说明受控机制，不可充当真实 LLM 搜索成功的证明。

### 4.2 机制指标

报告真实质量合格类别召回/精确率、误合并/误分离、近阈值未决率、区间覆盖率、补充 witness 次数与成本。真实参考集合已知时可以讨论 DWD/PR；必须说明有限域、参考集与归一化方式。

在每个配置做至少 30 次随机运行，主要比较指标预先确定为“给定预算下真实质量合格类别召回，且误纳低质量类别率不增加”。质量—覆盖面积与达到覆盖目标的成本为辅助指标。

## 5. 真实任务层与多模态输出用途

### 5.1 第一层：当前可运行的程序规则任务

- TSP：增加规模与分布移位，保留可精确求解的小规模校验；大规模采用可信求解器参考和明确 gap。统一局部搜索预算，禁止一个控制器额外获得 3-opt 或更长求解。
- 在线装箱：增加互补分布、对抗次序与长度迁移；规则不能查看未来物品。若所有方法总是 best-fit 质量，说明任务不具区分力，应在开发集先确认难度，不能为扩大主结果临时换测试分布。
- 分类评分规则：加入更多公开表格数据，至少同时含二分类、多分类、不同维度、类别不平衡与噪声任务。目标不是超越大型 AutoML，而是检验可迁移规则与有用替代策略。

至少选择 12 个方法开发任务与 20 个独立确认任务/数据集。每个确认任务采用 3 个预定划分、每划分 5 个独立搜索重复。若受预算限制可分层抽样，但应先固定各层数量。

当前 pilot/冻结复核的 TSP probe 为 10 城市，validation/test 为 12 城市；装箱 probe 为 32 物品，validation/test 为 64。后续辨识实验应先让 probe/witness/test 的规模和分布一致，再单独设置规模迁移组。否则观察到的关系改变混合了有限采样误差与分布移位，不能只用采样浓缩界解释。

### 5.2 第二层：与第六章主题更贴近的真实算法发现

从以下两类选择至少一类：

1. **优化器/更新规则发现。** 搜索可执行参数更新、预条件或学习率调度程序；用多类小型模型与数据训练，保留真实优化轨迹。训练 seed、训练步数、硬件与验证权限统一，最终测试使用新模型/任务。
2. **机器学习管线/agent 模块发现。** 在隔离环境中搜索特征变换、损失函数、推理/选择策略或有限 agent 模块；评价准确率、成本、错误互补和分布移位。程序依赖、网络权限、资源上限及失败处理统一。

这一层才有条件支持“自动机器学习算法发现”的完整外推。当前 priority(f) demo 只是该主题的有限子问题，不应用标题范围掩盖任务范围。

### 5.3 为什么需要多个模式

预先选择一种可操作用途：

- 由训练/验证数据学习的实例选择器，在新实例上选择候选程序；
- 固定容量、固定推理预算的组合器；
- 新约束出现时，从档案选择满足约束且质量好的替代规则；
- 低开销程序与高精度程序在不同场景可替换。

如果使用组合器，所有方法均允许同样的组合步骤、容量与后处理预算。候选集的 test oracle 最小损失只能作为潜在互补上界，不能当成可部署性能。最终主要用途指标必须来自不访问 test 标签的选择器。

## 6. 强基线与复现约束

| 层级 | 基线 | 必须控制或保留的部分 |
|---|---|---|
| 最低必要 | 共享种子、随机生成、quality、niche | 相同 LLM、语言、初始信息、执行预算、外部档案读法 |
| 机制替代 | 文本新颖性/MMR、每测试分数 signature、质量 UCB、成本感知 UCB | 调优预算相同，排除“只是换了个 bandit/距离”的解释 |
| 信息消融 | A/M；完整 A/W/M；无转移边；打乱边；无 witness；固定更多 probe | 信息量与额外费用明确，随机记忆作为信息对照，不用无意义 padding 伪装相同信息 |
| 最近邻 | MLEvolve、SeaEvo、AdaEvolve；适用时加 FunSearch/OpenEvolve、GEPA | 固定作者提交/论文版，保留实际检索、反思、迁移、策略抽样等组件，全部辅助费用计入 |
| 简单扩展 | 最近邻 + 同一个执行描述符/去重器 | 排除“最近邻加几行行为去重就达到同样结果”的解释 |

每个外部基线做两层报告：作者原版设置的合理复现，以及统一任务接口和预算下的适配。不同层级的数值不可混为一个排行榜。找不到作者代码时按论文重建并写明偏差；缺少 embedding/反思/迁移的缩减版不能称作完整 SeaEvo/AdaEvolve。

MLEvolve 已发现的停滞/奖励实现与文稿差异需单独记录并保留发布版/修正版结果。若某个上游组件实现与论文表述不同，先用最小例子确认调用路径，不能从单个函数就宣布整个框架错误。

## 7. 因果归因与敏感性

先做最小 2×2 设计：行为档案 A 开/关 × 有效重复关系调度 M 开/关。然后在已确定有效的核心上逐项检验 witness、成本收益率与 W，避免一次堆入所有模块。

必要消融：

1. 原 v1 collision 惩罚 vs 只惩罚无质量/用途增益的重复；
2. 无关系边、随机打乱边、仅标签计数、完整条件关系；
3. 固定重启率、原停滞阈值、置信度支持的重启；
4. 真轨迹、末端摘要、打乱时间顺序、随机等长前缀、无 W；
5. 固定 probe、同成本更大固定 probe、自适应 witness；
6. 相同候选数、相同 token 上限、相同 evaluator 预算三个设置分开报告；
7. 档案容量、质量容差、行为阈值和 witness 精度的预定网格。

敏感性网格只在开发任务调整最终默认参数；确认任务仅执行已登记网格并完整报告，不反向更改主方法默认值。未通过主要指标时，敏感性中的某一好点不算主方法通过。

## 8. 预算、规模与排期

建议分阶段花费，而非直接跑完整大矩阵：

| 阶段 | 示例规模 | 候选 token 上限总量 | 推进条件 |
|---|---:|---:|---|
| 已落实 v1 冻结验证 | 120 次 × 60k | 7.2M，另列基础设施失败开销 | 判断原完整方法是否有稳定增量 |
| v2 开发 | 12 任务 × 6 方法 × 3 搜索 × 1 模型 × 60k | 12.96M | 最小机制有效、无泄漏、描述符可辨识 |
| v2 核心确认 | 20 任务 × 4 方法 × 3 划分 × 5 搜索 × 2 模型 × 100k | 240M | 任务级效应与预定非劣条件通过 |
| 最近邻扩展 | 在冻结的代表任务层增加 3–5 个完整框架 | 按实际 API/反思/embedding 费用重新核算 | 完整实现可核验且协议公平 |

这些是设计上限，不是已执行量或经验证的必要最小样本量。240M 适用于全面确认；可先用开发方差做功效模拟，在不查看确认效果的前提下缩小或扩大正式样本数。用户账号有经费授权，但 Coding Plan 的速率与并发仍约束墙钟，应按真实吞吐量排期。

本机可以承担当前评分规则的 CPU 评价；优化器/训练管线层需要另测每个候选的 GPU 时间与内存，再给出训练任务数量。8 GB 显存适合小模型机制实验，不能据此承诺完整大型训练基准在三天内完成。

三天内合理验收范围：冻结原型追加验证、近邻审查、最小机制修改与少量独立复核。完整博士章节的跨框架和真实训练任务证据，应按测得吞吐量单独安排，不能用三天 demo 代替。

## 9. 正式统计方案

以任务为最高推断层级；同任务内划分与搜索重复是下级，不能将它们全当成独立新任务。每个任务先聚合相同条件的重复，再报告任务级配对效应与分层 bootstrap；多模型为预先设定的分层因素。

主要结论采用“质量优效且用途非劣，或用途优效且质量非劣”。非劣界必须有任务实际意义，依据开发数据或应用要求固定。质量改进和用途改进各有一个主指标，使用预定层级检验或 Holm 控制比较族。

同时报告原始单位的效应、区间、胜平负、最坏任务退化、无效候选比例、成本利用率。跨任务汇总使用明确的归一化改进或秩；原始 gap 与分类错误率不直接平均。对于 API 不可复现性，保存精确 prompts/responses/usage/返回模型 ID，并随机化运行顺序与时间块。

运行失败：语法/数值/超时属于算法结果并计入预算；明确的服务限流/中断为基础设施事件，按照事前修订规则处理。重复试验必须保留全部尝试及成本；禁止将失败删掉后只报告成功率。

确认样本量由开发数据的任务级方差、最小实际效应和功效模拟决定。当前 10 个重复块用于初步门槛；失败不代表证明两个方法等效。最终主实验应报告能排除多大效应，而不只给 p 值。

已做一项不依赖本轮实测效应的设计敏感性计算（results/power_sensitivity.json）：在正态配对差、单侧 t 检验和保守 alpha=0.05/24 假设下，10 个配对块达到 80% 功效需要约 1.53 个差值标准差的效应；30 块约需 0.73，50 块约需 0.55。它不是本轮符号翻转/交并门槛的实际功效，但说明 10 块更适合筛查大而一致的增量，不能可靠排除小收益。正式扩展应减少主比较数量、按任务分层，并据开发方差作功效模拟，而不是看未显著后随意追加到显著。

## 10. 章节验收与交付清单

能够形成正式方法章节至少需要：

- 问题定义区分外层算法模式与内层实例解，有限 probe 的局限明示；
- 新状态或决策规则有明确增量，不能被简单档案/质量 UCB/近期方法替代；
- 质量、用途和总成本在独立任务上按预定方案通过；
- witness 与 W 的贡献有归因，若无增量则删去或降为可选模块；
- 至少一个与真实机器学习算法/模块发现相关的任务层；
- 源码、环境锁定、任务划分、论文/代码版本、失败日志、全部种子与统计脚本可复核；
- 理论只声称已证明的条件性质，并报告计算开销和失效情形。

最终提交应包括技术路线图、算法伪代码、机制定义、复杂度与有限性质证明、基线来源表、主结果、成本图、消融、敏感性、失败案例和复现说明。若稳定增量仍不成立，第六章应转为执行模式辨识与失效分析等更窄问题，或继续开发新方法；不应把原 demo 包装成已证明有效的新算法。
