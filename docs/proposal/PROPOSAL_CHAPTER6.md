# 第六章 面向自动机器学习算法发现的执行辨识与关系记忆多模态搜索方法

> 更新至 2026-09-24：v1.2 已完成 18 次机制筛查。有限分支开发执行链达到预设触发门槛；关系引导调度的 test gap 高于同机会固定开发基线。该结果加强了工程可行性证据，同时限制了方法有效性主张。详细架构、逐运行数据和作废批次规则见[架构说明](../chapter6/V12_ARCHITECTURE.md)与[实验报告](../../experiments/chapter6/v12/results/screening-20260924-r2/TECHNICAL_REPORT_ZH.md)。

## 6.1 研究定位与结论口径

本章拟研究的问题不是让大语言模型简单地产生更多代码，而是在固定评价预算下，自动发现一组质量合格、行为有所区别并且具有实际替代价值的机器学习算法或算法模块。研究对象从前几章中的固定优化问题和给定算法，扩展为“程序本身作为搜索个体”的外层算法发现问题。

结合截至 2026 年 9 月 24 日的材料，已有证据支持以下判断：

1. **研究问题具有科学性。** 程序文本、执行行为、质量收益和搜索成本并不等价；有限执行探针可能把有质量收益的局部开发误判为重复，这一现象可以定义、测量并被独立实验否证。
2. **研究路线具有工程可行性。** 已经实现 planner—coder—受限执行—质量评价—A/B 状态更新闭环；v1.2 在两个模型端点、三个配对区块和 18 次运行中完成日志记录与机制回放，并触发 30 次分支后续评价。
3. **最终算法有效性尚未被证明。** v1.2 的关系分支 test gap 均值高于 `niche + fixed development` 基线（6.379% 对 5.569%），每臂仅六次运行，不能把差异解释为确认性效果；当前数据不支持关系调度的质量优势。
4. **创新性属于待验证命题。** MLEvolve、FunSearch、SeaEvo、AdaEvolve 和 GEPA 已覆盖多种相邻机制。本章必须通过强基线和消融证明所提执行关系判断有不可替代的增量；若固定开发基线即可解释结果，应收窄或删除关系导航主张。

因此，本章应表述为“具有明确科学问题、工程可行性和可执行验证路径的研究方案”，而不是已完成的博士新算法。v1.2 已把局部改进转为真实受限开发机会，但其关系调度未超过强简单基线；后续需先诊断这一负结果，再决定是否扩展。若后续版本未通过独立确认门槛，本章应以执行机制比较和失效边界为主，收窄创新主张。

## 6.2 研究背景与问题提出

### 6.2.1 从多模态优化到算法发现

多模态优化要求在有限评价预算内同时获得多个高质量且具有决策差异的解。第四章的 MSLS-MA 研究表明，在离散多模态旅行商问题中，仅追求当前最优路线会造成模式丢失，需要将小生境维护、局部开发和停滞重启结合起来。第五章的 RMC-CMSA 进一步区分了竞争性解档案、搜索轨迹证据和终端覆盖记忆，指出搜索起点与局部搜索终点之间可能存在显著不一致，重启分配不能只依据起点或最终精英。第三章关于质量—多样性指标和测试问题的研究，则提供了同时评价质量和覆盖的实验原则。

在自动机器学习算法发现中，搜索个体不再是固定问题上的一个解，而是一个可执行程序、规则或算法模块。一个程序在一组实例上的输出、错误案例、资源消耗和中间轨迹共同决定其实际用途。两个程序可能在源代码上差异很大，却在有限测试样本上产生相同决策；反过来，两个程序也可能在固定 probe 上行为相同，但在新实例上产生不同质量。因而，算法发现中的“多模态”不能简单等同于代码字符串多样性，也不能只统计不同的策略标签。

### 6.2.2 现有智能算法发现系统的不足

MLEvolve 已经利用渐进式图搜索、跨分支引用、回溯记忆和 planner/coder 解耦解决了一部分分支隔离、经验遗忘和规划—编码耦合问题。FunSearch 的程序数据库使用测试得分签名和岛屿机制维护执行结果差异。SeaEvo 已使用策略表示、验证成功向量和互补覆盖来导航策略空间。AdaEvolve 已研究基于改进信号的探索强度、岛屿资源分配、迁移和动态生成。GEPA 则使用轨迹反思、Pareto 候选选择和跨谱系合并。因此，本章不能把“有记忆”“有多个候选”“会重启”“让模型反思”单独写成首次贡献。

仍然存在四个可以检验的空缺：

1. **执行关系的不确定性。** 固定 probe 只提供有限样本上的关系，不能自动成为程序在目标分布上的等价证明；近似相似关系还可能不具传递性。
2. **相似与无收益重复的混淆。** 一个候选可能与已有程序行为相近，但在相同模式内部取得可靠质量改进。若所有 collision 都受到惩罚，调度器会主动压制有价值的局部开发。
3. **多通道记忆的条件作用不清楚。** 终端行为、真实轨迹、规划意图和成本可能包含不同信息，也可能存在冗余。必须检验 W 在已有终端和质量信息之后是否仍有增量，而不能预设 A/W/M 三者都必然有效。
4. **成本与收益没有统一归因。** planner、coder、反思、embedding、witness、程序修复和执行都消耗预算。只报告最终质量而不报告这些成本，无法说明固定预算下的搜索优势。

### 6.2.3 核心科学问题

本章围绕以下问题展开：

**问题一：** 有限执行证据在什么条件下会误合并或误拆分程序行为模式？独立 witness 是否能在可接受的附加成本下改善关系辨识？

**问题二：** 在质量门槛和总预算固定时，区分“有用的模式内开发”“有用的新模式”“尚不确定的候选”和“无收益重复”，是否能改善搜索的质量—行为覆盖折衷？

**问题三：** 起始模式、操作类型、真实轨迹和终端模式之间是否存在可预测的条件转移关系？这些关系是否能带来超过质量 UCB、简单小生境、随机关系图和文本新颖性方法的增量？

**问题四：** 该机制能否从规则发现任务迁移到至少一类真正的机器学习算法或算法模块发现任务，并且在相同模型、候选数、token 和执行预算下保持收益？

## 6.3 研究目标与可证伪假设

### 6.3.1 总体目标

构建一种面向自动机器学习算法发现的执行反馈多模态搜索方法。该方法在有界程序接口内，以质量为硬约束，以可辨识的执行行为和实际用途为多样性依据，以 A/W/M 三类状态记录起始—操作—终端关系，并在资源约束下分配局部开发、跨模式引用、补充辨识和重启机会。

### 6.3.2 可证伪假设

设 (p,q) 为合法程序，(L(p)) 为目标分布上的质量损失，(b(p,x)) 为程序在实例 (x) 上的行为，(d(p,q)) 为行为距离，(U(S)) 为候选集合 (S) 在预定义用途上的覆盖收益，(C) 为完整搜索成本。

提出以下待检验假设：

- **H1（辨识假设）：** 在存在稀有分歧行为或有限样本的情况下，固定小 probe 对 (d(p,q)) 的判断会产生可测量的误合并或误拆分；独立 witness 的三态区间判断能够降低错误率，但会增加执行成本。
- **H2（质量保护假设）：** 相对于对所有行为碰撞统一惩罚的 v1，只有在“质量无显著改进、用途无增量且关系已确认接近”时才惩罚重复，能够在相同总预算下保持质量非劣并提高有用行为覆盖。
- **H3（关系记忆假设）：** 起始模式和操作到终端模式的条件关系，在时间外或任务外数据上能够预测下一次质量增益或用途增益；关系打乱后该预测能力和搜索收益应下降。
- **H4（轨迹增量假设）：** 在已经给出父代、终端、质量和成本信息的条件下，真实中间轨迹 W 对终端结果或下一次增益仍具有稳定的独立预测作用；若不成立，则应删除 W 或将其降为可选模块。
- **H5（外部有效性假设）：** 在至少一种优化器、更新规则或机器学习管线模块发现任务上，完整方法相对于强基线的优势不能由更多 token、更多候选、宽松质量门槛或不公平的测试反馈解释。

以上假设均有明确的否证方式。若 H2 或 H3 不成立，本章不应继续宣称关系记忆带来稳定搜索优势；若 H4 不成立，则简化后的 A/M 方法仍可作为候选方法，但不应保留 W 作为核心创新。

## 6.4 问题定义与多模态程序空间

### 6.4.1 程序、任务和质量

对任务 τ，给定实例分布 Dτ、有界程序语言 Pτ、输入输出契约和运行资源限制。程序 p∈Pτ 在实例 x 上产生输出 y_p(x)、行为 b(p,x) 和资源消耗 c(p,x)。其目标质量为

$$
Lτ(p) = E_{x~Dτ}[ℓτ(p,x)].
$$

算法发现的输出不是单一最低损失程序，而是一个满足共同质量门槛并且具有可验证差异和用途的集合：

$$
Fτ = {p : Lτ(p) <= Lτ(p0) + ετ}.
$$

其中 p0 是预先固定的参考程序，ετ 由开发任务和应用意义确定。外部方法比较使用共同门槛，不能按照各方法自身表现事后调整容差。

### 6.4.2 行为空间与用途空间

在独立实例集合 Xτ = {x1, …, xm} 上定义经验行为距离

$$
d_hatτ(p,q) = (1/m) Σ_i δ(b(p,xi), b(q,xi)),   0 <= δ <= 1.
$$

TSP 可以使用路线边集 Jaccard 距离和实例级路径代价，在线装箱可以使用共箱关系、箱数和溢出行为，分类规则可以使用逐样本预测向量、错误案例集合和资源开销。行为描述符必须保持任务语义；AST 或代码 embedding 只能作为检索辅助，不能替代执行证据。

对候选集合 (S)，本章同时报告：

1. 质量指标，例如 gap、错误率或训练损失；
2. 质量门槛内的行为代表数和行为覆盖；
3. 预先定义的用途指标，例如错误互补、约束切换后的可替代性或固定容量组合器的独立验证表现；
4. planner、coder、执行、witness、修复和失败调用的完整成本。

“模式更多”只有在质量和用途不恶化时才具有正面意义。候选集合在最终 test 上的最小损失只能作为离线互补上界，不能作为可部署选择器的性能。

## 6.5 拟议方法：质量保护的执行关系搜索

### 6.5.1 总体流程

方法流程为：

1. 固定任务契约、程序语言、初始规则、预算和数据隔离边界；
2. 由 planner 提出带有意图和操作类型的候选计划，由 coder 生成受限程序；
3. 在统一 probe 和 validation 上执行候选，检查语法、数值、资源和质量；
4. 将候选与 A 中代表、W 中轨迹和 M 中历史关系进行匹配；
5. 只有在关系接近阈值或将影响重启、替换和档案决策时，抽取独立 witness；
6. 以“质量增益—行为关系—用途增益—成本”四个维度更新状态；
7. 在质量保护规则下选择继续局部开发、跨模式引用、重新激活或重启；
8. 搜索冻结后，只在未反馈的 audit/test 上进行一次最终评价。

### 6.5.2 三类状态的定义与分工

**A：质量竞争档案。** 保存通过共同质量门槛、并且已经获得足够行为证据的程序代表。A 用于最终候选输出、父代选择和互补检索，不把 A 的数量直接解释为全局真实模式数。

**W：轨迹证据。** 保存程序实际执行过程中按时间或改进步骤产生的中间状态、前缀和增量。W 只有在控制了父代、终端、质量和成本后仍有预测增量时，才作为核心状态；任意重排的样本前缀不自动具有轨迹意义。

**M：关系与成本记忆。** 保存起始模式、操作类型、终端模式、质量变化、用途变化、关系置信状态、失败类型和已消耗成本。M 的作用是支持调度、重启、重新激活和补充辨识，而不是把所有低分候选永久删除。

对每个候选记录

$$
e_t = (a_t, o_t, z_t, ΔL_t, ΔU_t, c_t, h_t).
$$

其中 at 为起始或父代模式，ot 为 refine、引用、重组或 restart 等操作，zt 为终端代表或未决关系，ΔLt 为质量变化，ΔUt 为用途覆盖变化，ct 为实际成本，ht 为关系证据状态。

### 6.5.3 独立 witness 的三态关系判断

固定 search-probe 只用于低成本筛选。对影响档案替换、重启和资源分配的关系，在候选程序确定后独立抽取 mt 个 witness 实例，并计算 d_hat_t。当第 t 次比较的候选数不超过 Jt 时，取

$$
e_t = sqrt( log(2 Jt / αt) / (2 mt) ).
$$

关系判断为：若 d_hat_t + et < ρ，则确认接近；若 d_hat_t - et > ρ，则确认分离；其他情况记为不确定。

当 Σt αt <= α 且 witness 在程序确定后独立抽取时，Hoeffding 不等式和并集界给出：所有登记关系区间同时覆盖真实分布距离的概率至少为 1 - α。该性质只保证已比较程序在给定分布上的辨识区间，不保证关系传递、不保证发现全部模式，也不保证 LLM 能到达未探索区域。若根据结果反复追加 witness 并随时停止，必须使用有效置信序列或为每次查看重新分配误差额度。

### 6.5.4 质量保护与收益—成本调度

设 ηQ 和 ηU 分别为质量和用途的最小实际意义门槛。候选处理规则为：

- 若 ΔLt >= ηQ，保留该候选的局部开发路径，即使其与已有代表确认接近；
- 若质量非劣且 ΔUt >= ηU，将其视为有用新模式或有用替代，而不是重复；
- 只有在关系确认接近、ΔLt < ηQ、ΔUt < ηU，并且额外成本超过预定阈值时，才将其计为可避免重复；
- 关系不确定时保留继续、补充 witness 或延后决策的机会，不直接永久惩罚。

候选操作族 o 的收益可以写为

$$
r_t = ΔQt + λ ΔUt.
$$

$$
S_t(o) = (μ_hat_r(o) + βt u_r(o)) / max(cmin, μ_hat_c(o)).
$$

实际第一版采用质量优先的词典序约束：先排除质量明显退化的操作，再比较经过校准的用途收益率和探索不确定性。式中的 λ、βt 和成本下限必须在开发任务上固定，不能在确认任务上根据结果调参。该表达式是候选调度规则，不构成一般非平稳 LLM 搜索的后悔界。

### 6.5.5 算法伪代码

```text
Input: task contract, initial programs P0, budget B, quality tolerance eps,
       behavior threshold rho, witness schedule, operation set O
Initialize A from P0, W from real traces, M from empty relation records
while admissible_cost(B) and not frozen:
    choose operation o using quality-protected cost-aware scheduler
    p <- planner_and_coder(o, A, W, M)
    if p violates syntax/resource contract: record failure in M; continue
    evaluate p on probe and validation with common gates
    estimate quality gain, behavior relation and utility gain
    if relation affects archive/restart decision:
        draw predeclared independent witness and assign close/far/uncertain
    update A, W, M and relation graph
    preserve quality-improving same-mode development
    penalize only confirmed low-quality, low-utility repetition
freeze parameters, archive and selector
evaluate once on independent audit/test; report quality, utility, behavior and cost
```

## 6.6 可证明性质与理论边界

### 6.6.1 Witness 辨识性质

在程序已经确定、单实例距离位于 ([0,1])、witness 条件独立且每次比较数受 (J_t) 限制的条件下，上述 (e_t) 给出同时置信区间。该结果解释了为什么关系判断应设置“不确定”状态，也解释了为什么固定 probe 的点估计不能被直接当作程序等价证明。

### 6.6.2 档案条件有效性

如果每个入档程序都通过共同质量门槛，并且与已有代表的关系下界在置信事件上超过 ρ，则输出档案在该置信事件上满足相应质量约束和两两分离条件。该性质是条件性质：贪心档案不保证最大覆盖基数，LLM 生成过程也没有完备性保证。

### 6.6.3 预算审计性质

对 planner、coder、witness、执行和修复分别记录调用上界，并且只在保守输入上界和输出上界可支付时发起请求，则在提供方 usage 契约有效的区块内，总 token 不超过预设预算。提供方错误但没有返回 usage 时，远端消耗不能被推断，应将该区块列为成本不可确认，而不能假定消耗为零。

### 6.6.4 不作出的理论承诺

本章不承诺开放程序空间上的全局收敛、模式完备发现或一般 bandit 次线性后悔界。原因是候选空间由 LLM 非平稳地产生，评价之间存在相关性，档案和关系图动态变化，标准随机优化的直接条件并不成立。理论部分只证明有限 witness 辨识、条件档案有效性和可审计预算，不把有限性质扩大为算法全局最优性。

## 6.7 实验设计与章节验收

### 6.7.1 实验分层

| 阶段 | 研究目的 | 主要设置 | 通过条件 |
|---|---|---|---|
| A. 受控机制实验 | 测量 probe 误合并、误拆分和 witness 成本 | 有限状态、有界 DSL、可枚举真实行为类；每个预选配置至少 30 个随机重复 | witness 在相同成本比较下显著降低错误，且未决率和开销被报告 |
| B. 方法开发 | 固定 v2 规则、阈值和操作集合 | 12 个开发任务；允许修改提示、关系表示和超参数 | 质量保护规则不压制已知的有益同模式开发；不存在数据泄漏 |
| C. 独立确认 | 检验质量、用途和成本的共同增量 | 至少 20 个任务级单元，3 个独立划分，5 个搜索重复，2 个模型 | 预注册主要指标达到质量优效且用途非劣，或用途优效且质量非劣；任务级区间和最坏退化同时满足要求 |
| D. 真实算法发现 | 检验章节主题外推 | 优先选择优化器/更新规则发现，备选为机器学习管线或 agent 模块发现 | 在新模型或新任务上相同预算下保持收益，并通过最近邻强基线和完整消融 |

阶段 A 的有限域实验只能证明辨识机制在受控条件下的性质，不能代替真实 LLM 任务；阶段 D 才能支持“自动机器学习算法发现”的完整外推。

### 6.7.2 受控机制基准

有限域设置 16—32 种状态、4—8 种动作和有界算术/条件规则。枚举所有合法程序的行为向量并严格去重，得到真实行为类。系统预先改变等价改写倍率、模式频率不平衡、稀有分歧概率、起始—终端汇聚强度和质量噪声。质量相近但行为不同的类别与质量差的远距离类别同时存在，防止只靠新颖性得分取胜。

主要指标为质量合格类别召回、低质量误纳率、误合并、误分离、近阈值未决率、区间覆盖率、witness 次数和总执行成本。固定小 probe、固定大 probe、独立 witness 和穷举真值必须在相同成本或分开成本条件下报告。

### 6.7.3 真实程序搜索任务

第一层保留当前可运行的三类任务：

1. **TSP 规则发现：** 搜索能够在新实例上构造路线的评分函数；报告 gap、路线边集差异、分布移位和规模变化。小规模使用精确求解器校验，大规模使用明确的参考求解器和 gap 定义。
2. **在线装箱规则发现：** 搜索不访问未来物品的放置评分函数；加入互补物品分布、对抗次序和长度迁移，报告箱数、溢出、共箱行为和规则成本。
3. **分类规则发现：** 在二分类、多分类、类别不平衡和噪声数据上搜索评分规则；统计特征、阈值和预处理只使用 fit 数据，验证用于选择，test 只在冻结后使用。

第二层至少选择一类与机器学习算法发现直接相关的任务。优先方案是**优化器/更新规则发现**：在固定的模型族、训练数据、训练步数、随机种子和硬件预算下，搜索参数更新、预条件或学习率调度程序；最终在未参与搜索的新模型和新数据上评价收敛曲线、最终损失、跨种子稳定性、资源消耗和失败率。若采用机器学习管线或 agent 模块发现，则应统一依赖、网络权限、运行时、内存和异常处理。

### 6.7.4 基线与消融

确认实验至少包含以下基线：

- 共享初始程序、质量选择和简单小生境；
- 质量 UCB 或成本感知 UCB；
- 文本新颖性/MMR 和执行分数 signature 聚类；
- 无关系边、随机打乱关系边和仅标签计数；
- A/M、A/W/M、无 witness、固定更大 probe；
- 适用时的 MLEvolve、SeaEvo、AdaEvolve、FunSearch/OpenEvolve 或 GEPA 复现/适配版本。

外部框架必须锁定来源、版本和接口。缺少作者实现时可以按论文重建，但须说明缺失组件；缩减版本不能称为完整框架。所有 planner、coder、反思、embedding、witness、执行和修复调用均计入成本。

核心消融采用分阶段设计：

1. 行为档案 A 开/关 × 关系调度 M 开/关；
2. 原 v1 collision 惩罚、质量保护重复判定和随机关系图；
3. 固定 probe、同成本大 probe 和独立 witness；
4. 真实轨迹 W、末端摘要、打乱时间顺序、随机等长前缀和无 W；
5. 固定候选数、固定 token 上限和固定 evaluator 预算三个独立控制条件；
6. 行为空间阈值、质量容差、档案容量和 witness 精度的预注册敏感性网格。

### 6.7.5 评价指标与统计

主指标为验证选择后的独立 test 质量，以及共同质量门槛下的有用行为覆盖。辅助指标包括错误互补、约束切换可替代性、重启效率、可避免重复比例、总 token、墙钟时间、CPU/GPU 时间、无效候选率和失败率。

统计以任务为最高推断层级。相同任务内的划分和重复使用配对块效应，模型作为预先设定的分层因素。报告任务级效应、95% 置信区间、胜平负、最坏任务退化和成本利用率。主比较数量预先固定并使用 Holm 或分层置换/符号翻转控制多重性；gap、错误率和模式覆盖不直接跨任务取原始平均。

当前冻结 v1 验证使用 10 个配对划分，适合筛查大而一致的增量，不能排除小幅收益。正式确认的重复数应根据开发任务方差、最小实际效应和功效模拟冻结，不能根据确认结果追加到显著为止。

### 6.8.2 科学性判断

本研究的科学性来自四个方面：第一，研究对象和评价量可以形式化；第二，提出了明确的可证伪假设；第三，存在受控真值实验、独立数据隔离和强制失败报告；第四，已有反例使机制修改有明确动机，而不是只为追求正结果增加组件。科学性并不意味着结论必然为正，而是意味着正、负和条件性结果都能改变研究结论。

### 6.8.3 可行性判断

当前程序规则层已经在 Windows 11、Python 3.13、NumPy/SciPy/scikit-learn/Matplotlib 等环境中运行；本机有 28 个 CPU 线程，TSP、装箱和小型分类任务可以在 CPU 上评价。Qwen3.7-Plus、MiniMax-M3 等 Coding Plan 已完成真实调用，后续可按速率限制接入 Kimi、智谱、DeepSeek 等已授权模型。已有验证在 60,000 token/区块的硬上限下完成，说明小规模机制和规则发现任务具有工程可行性。

可行性边界也必须写清楚：当前证据没有测得 GPU 训练任务的端到端吞吐，不能承诺大型模型优化器发现能在三天内完成；Coding Plan 不消除并发限制，MiniMax 首批限流和一次 Qwen 超时已经证明需要低并发、重试登记和基础设施排除规则。后续真实训练任务应先测单候选 GPU 时间、显存、失败率和模型训练稳定性，再冻结规模。

## 6.9 风险、替代路径与开题验收门槛

| 风险 | 可能表现 | 处理方式 |
|---|---|---|
| witness 成本过高 | 关系辨识正确但吞噬搜索预算 | 先做同成本比较；采用不确定状态和分层 witness；若无净收益，保留固定 probe 并下调主张 |
| W 没有独立信息 | 完整 A/W/M 与 A/M 相同 | 删除 W，转为 A/M 关系记忆；将 W 作为分析变量而非核心模块 |
| 关系图不能预测收益 | 打乱边与真实边效果相同 | 放弃“关系导航”主张，保留质量保护档案或重新定义操作状态 |
| 任务区分度不足 | 所有方法收敛到同一规则 | 在开发集证明任务难度；不在确认阶段临时更换分布 |
| 外部框架无法公平复现 | 缺少源码、embedding 或反思实现 | 分开报告作者版复现与统一接口适配，不给缩减版排名 |
| API 非平稳或限流 | usage 缺失、超时、调用速度变化 | 低并发、完整保存失败区块、预先规定基础设施修订，不把失败删除 |
| 结果仍不稳定 | v2 未达到共同门槛 | 将第六章收窄为执行模式辨识与失效分析，不把负结果改写为算法优越性 |

正式章节的最低验收条件为：

1. 程序空间、行为距离、质量门槛、用途和成本定义完整；
2. 至少一个新机制相对于简单小生境、质量 UCB 和关系打乱具有独立增量；
3. A、W、M 的作用通过消融归因，若某模块无增量则删除或降级；
4. 在独立任务上质量和用途至少一个显著优效且另一个非劣，同时没有不可接受的最坏任务退化；
5. 至少一类真实机器学习算法或模块发现任务通过相同预算比较；
6. 源码、数据划分、提示、模型版本、usage、失败记录、统计脚本和环境均可复核。

若只满足前两项，应将成果写成机制研究；若满足前三项但真实 ML 任务未通过，应限制题目为“执行反馈程序搜索”而不是泛化为完整 AutoML；只有全部门槛满足后，才可以把本章表述为新的自动机器学习算法发现方法。

## 6.10 研究计划与预期成果

建议按以下顺序推进：

1. **第 1—2 个月：** 完成有限 DSL、真值行为类、witness 置信程序和同成本固定 probe 对照，冻结 H1 的统计方案；
2. **第 3—4 个月：** 在开发任务上实现质量保护重复判定、A/M 最小版本和关系打乱对照，决定 W 是否进入核心方法；
3. **第 5—7 个月：** 完成独立规则发现确认，锁定默认参数、统计门槛和失败分类；
4. **第 8—10 个月：** 完成至少一种优化器、更新规则或机器学习管线模块发现任务，并接入适用的近期强基线；
5. **第 11—12 个月：** 完成理论条件、消融、敏感性、成本和失效案例，整理代码、数据、日志和论文。

预期成果包括：

- 一个有界、可执行、可审计的执行关系搜索框架；
- 有限 witness 关系辨识的条件性质和成本分析；
- 质量保护的多模态算法发现调度器及其消融证据；
- 受控机制基准、规则发现任务和至少一种真实 ML 算法发现任务；
- 公开的完整日志、失败样本、程序回放脚本和可复现实验环境；
- 对方法有效范围、失效条件和与 MLEvolve/SeaEvo/AdaEvolve/GEPA 差异的明确说明。

本章可能产生三种科学结论：若 v2 在独立任务上通过质量—用途—成本门槛，则形成正式的新方法章节；若只有 A/M 通过，则以简化关系记忆方法为主并删除 W；若所有版本均未超过强基线，则以有限执行证据的模式辨识、重复误判机制和负结果为主要贡献。三种结果都符合科学研究的可证伪逻辑，但不能用同一套标题和主张表述。

## 6.11 本章小结

本章将前述多模态优化研究中的质量与结构分离、小生境维护、局部开发、起点—终端不一致和多通道记忆原则，迁移到自动机器学习算法发现的程序空间中。迁移的关键不是把已有算法模块机械拼接到 LLM agent，而是回答一个更具体的问题：在有限执行证据和固定预算下，如何识别有用的行为差异，保护质量改进，并用可审计的关系记忆安排后续搜索。

已有实验已经证明该问题可以被真实模型、受限解释器和独立日志系统研究；v1.2 又证明了有限分支开发可以在搜索中被实际触发。但关系引导没有超过同机会固定开发基线，当前尚未证明方法有效或形成可部署的多算法集合。因此，本章的开题结论应为：**研究问题科学、技术路线具备工程可行性，分支执行机制已经过机制筛查；关系调度的增量、最终方法有效性和博士创新性仍需通过更大规模独立实验及真实机器学习算法发现任务证明。**
