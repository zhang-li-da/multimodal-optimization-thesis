# 第六章研究方案：质量保护多模态程序搜索与有限分支开发

更新日期：2026-09-26。对应 v1.2.3 真实筛查；本稿用于开题报告中的研究内容、技术路线和研究基础。已完成实验的数值以 [技术报告](../../experiments/chapter6/v12_3/results/minimax-20260926-r1/REPORT_ZH.md) 为准。关系图、轨迹调度、witness 等更广设想保留在旧稿中，本稿将近期核心问题收窄到可以被独立实验检验的分支开发机制。

## 6.1 研究背景与前序工作的承接

多模态优化除了求得一个高质量解，还关注多个可替代方案的维护及其用途。第三章关于多模态优化机制和质量—分布评价的研究，为区分质量、行为差异和集合用途提供原则；第四章 MSLS-MA 与 RMC-CMSA 为多结构维护、模式内开发和依据实际搜索结果分配资源提供基础；第五章 HDADE 关于质量与决策空间结构的分别维护，为避免单一质量排序淘汰有潜力候选提供思路。

第六章将外层搜索对象从一个解扩展为可处理新实例的程序。程序经模型修改后，在冻结实例上执行并反馈结果，再由控制器决定哪些候选应输出、哪些分支应获得有限的继续开发机会。本章的多模态指多个质量合格、执行行为不同且可能有互补用途的程序模式，与图像、文本等输入模态无关。

这种迁移不意味着可以直接套用前序算法的效果结论。路线局部邻域与代码修改邻域不同，程序空间缺少完整模式参考集，有限 probe 行为相似也不是程序全分布等价的证明。多个策略标签不能作为多个真实算法模式的证据。

## 6.2 科学问题与研究目标

核心问题是：**在有限行为评价和模型生成预算下，如何区分已知规则重现与值得继续开发的局部进步，并将有效进步兑现为可执行、有上限的分支资源分配？**

前期研究发现，质量相近程序的行为碰撞不必然表示开发无益；仅在统计上补记父代进步，也不保证候选能够再次被选择。将档案 A 的行为去重与父代选择完全绑定，会使“承认进步”和“继续开发”脱节。因此拟将输出代表维护与开发机会维护分开，并检验其价值。

研究目标分为三个层次：首先保证合格局部进步能够获得实际而有限的执行机会；其次比较不同分支选择规则能否产生超过简单 FIFO 的增量；最后检验保留多个程序能否通过可部署选择器改善新实例表现。三个层次各自需要证据，不能以原型运行成功替代效果验证。

## 6.3 操作性定义与最小方法

设 p 为受限程序，x 为实例，L(p) 为实例分布上的期望损失。搜索阶段仅可获得有限 probe 执行行为和 validation 损失向量。程序文本与分配标签用于记录和生成，质量与行为关系以实际执行为依据。

候选 p′ 相对父代 p 的进步为 Δparent=Lval(p)−Lval(p′)，相对当前最好的进步为 Δglobal=Lbest−Lval(p′)。两个量分别记录。若候选与某个历史有效规则的 probe 行为和 validation 损失向量都完全相同，标记为“已知规则重现”；它可以优于自己的父代，但不因此重置开发额度。其余质量合格、具有实质父代进步的候选可申请有限开发机会。

系统包括：

1. **A：输出档案。** 维护质量门槛内的有限行为代表，承担结果输出与普通搜索父代来源。代表数作为档案结构指标，不解释为真实模式召回。
2. **B：有限开发池。** 与 A 独立，保存有上限的分支机会。当前容量为 3、每条 2 次；非法子代同样消耗机会，已知重现不能续命。
3. **M：执行反馈。** 保存父代、分配方向、质量变化、候选分类、成本和实际额度消费。

W 在当前版本中不参与调度；保留的轨迹只是诊断资料。完整关系图、witness、不确定性调度只有在出现明确问题且独立证明增量后再引入。

两种已接入控制器共享普通 niche 调度与提示，仅在 B 内选父代不同：F 用严格 FIFO；R 使用 q(tag)+0.25×gain/(1+attempts)。q 是平滑历史改进频率，少于两次标签观察时回退到共享统计，不是预测概率。

执行流程为：冻结协议和数据 → 共同初始化 → 选择父代与操作 → planner 计划 → coder 程序 → 受限执行和评价 → 扣除已有额度并判断候选准入 → 搜索预算结束后按 validation 冻结输出 → 全部搜索结束后独立 test。每个阶段保留请求、原响应、身份哈希、决策、程序和失败记录。

## 6.4 可证伪的近期假设

| 假设 | 必需对照 | 支持或收缩依据 |
|---|---|---|
| 有限 B 开发能够创造超过普通搜索的增量 | 无 B 的 N 与 FIFO 的 F，其余完全一致 | 比较质量、成本及最终集合；仅发生更多续开发不算支持 |
| 局部收益排序优于固定顺序 | G 与 F | 相同准入、淘汰和总预算下是否改善独立 test |
| 族信息提供收益排序之外的价值 | R 与 G，必要时增加族对应打乱 | 首先有实际不同选择，再检验是否有稳定质量增量 |
| 行为多样性集合提供独立用途 | 同容量 top-K 质量集合与行为集合 | 同选择器、独立数据、冻结后部署；仅优于单程序不足以支持 |

若 F 有收益而 R 相对 G 无增量，应保留简单有限开发机制，收缩关系信息主张。若行为集合不能超过同容量质量集合，应报告多个候选的用途与行为多样性的贡献尚未分离。允许负结果和适用边界，不能预设“增加运行次数就会支持假设”。

## 6.5 已完成基础与本轮发现

旧 v1.2 r2 的 18 次真实搜索已经展示“识别进步—保留分支—继续执行”的链条，但普通调度和 W 等因素混杂，不能隔离排序效果。v1.2.1 与 v1.2.2 修复了共享调度、W 关闭、严格 FIFO、深度口径、ZIP/程序哈希与独立测试入口。

本轮 v1.2.3 在公开冻结协议后，使用本机 MiniMax M3 完成 16 次真实搜索：两控制器、八个新区块，每次 8 提案。数据为 14 城市 TSP，probe/validation/test 各 12/36/60 个实例，每块两组共用。原双模型草案保留，当前证据只来自一个模型。

| 本轮证据 | 结果 | 解释 |
|---|---|---|
| 完成度 | 16 搜索、16 独立 test、128 提案 | 真实执行和测试隔离成立 |
| 平均 Test gap | F 5.9833%，R 6.1019% | R−F 为 +0.1186 个百分点，未建立优势 |
| 八个配对 | R 3 胜、2 平、3 负 | 小样本筛查，无确认性结论 |
| 生成成功 | 25 有效程序、103 解析失败 | 输出预算成为进入机制前的瓶颈 |
| B 实际执行 | 两组各 9 次，共 3 个有效续开发子代 | 有限开发规则实际运行，失败也扣额度 |
| 多分支竞争 | 0 次 | 本轮没有充分检验分支间排序 |
| 同历史政策审计 | 128/128 决策和提示相同 | 不可把性能差值归因为排序动作 |
| 数值与重放 | 128 决策重放、32 次最终程序重评一致 | 结果可核验，不是新增效果实验 |

主差值描述性 95% 区间为 [−0.3416，+0.7491] 个百分点，基于八个数据块配对重采样，不把测试实例当作独立重复。完整组实际使用 token 比 FIFO 少约 1.84%，但有效输出更少，不构成成本效率优势的证据。

失败诊断发现 100 次 planner 输出截断，其中 98 次没有思考块之后的最终文本，2 次只有不完整计划；另有 3 次 coder 截断。当前简单连通性检查没有验证任务形态输出是否能在预算内完成。本轮参数保持冻结，失败原样保留；下一批应首先解决这一明确问题。

目前可以将系统与前期结果作为开题研究基础并展示 [离线 demo](../../experiments/chapter6/v12_3/results/minimax-20260926-r1/demo/index.html)。不能将它表述成“关系排序已有效”或“多模态算法集合已经具有部署收益”。

## 6.6 后续技术路线与实验设计

第一阶段是模型输出准备。选用独立于搜索与测试实例的工程用例，检验完整计划和完整代码输出；明确供应商模型信息、思考配置、输出上限和失败规则，随后冻结。它解决可执行输入问题，不作为方法效果实验。

第二阶段是机制可观测性。使用固定合成历史验证共享普通步骤一致、B 内排序能在同收益条件下响应不同族证据、失败正确扣费。真实运行中按模型×控制器分别统计入池、多分支、族分化、选择差异和后续改进。如果 8 步不足，则在新协议中统一增加各组预算；不能只增加 R 或删除未触发运行。

第三阶段统一 N/F/G/R 的正式在线接口，保持准入、淘汰、提示和预算一致，先探索后确认。主分析以区块级配对差值为单位，报告全部失败和 token、时间、评价成本；避免只展示平均值而不展示每个配对。关系信息增量用 R−G 检验，必要时以族对应打乱补充归因。

第四阶段冻结已生成程序，不增加生成量即可开始集合用途实验。独立划分选择器训练、开发和部署测试，比较验证最佳单程序、初始规则集合、同容量 top-K 质量集合、质量约束的行为集合。使用相同选择器、相同训练预算、预定 K 和置信不足回退规则，冻结后计入选择与试运行成本。Oracle 逐实例最优仅作为集合潜力上界。

第五阶段依据独立筛查方差与预设实际收益阈值规划确认样本量，不以“40 次”作为普适充分条件。若主张通用算法发现，需要性质不同的第二任务；增大 TSP 城市规模不能替代跨任务验证。最终方法、确认数据、模型参数与统计规则在确认运行前再次冻结。

## 6.7 拟形成的贡献与风险控制

候选贡献是：面向有限执行证据的程序进步分类、输出档案与开发机会的分离、可执行且受预算约束的分支资源分配，以及质量/行为/用途分层评价。实际创新强度取决于与既有程序搜索、记忆和调度方法的区别，以及强简单基线和独立归因结果。MLEvolve 等已有规划编码分离与记忆机制，不把这些通用组件写为首次提出。

当前最明确风险是模型输出消耗预算、有效候选稀少、分支竞争不足、族标签含义不稳定和验证集自适应使用。应通过独立工程准备、统一预算的触发实验、分组机制日志、独立选择器数据与测试隔离逐项处理。复杂图记忆和更多 agent 模块不是当前证据缺口的替代物。

本章近期验收是“机制可观察、执行可追溯、对照可解释”，最终验收才是“方法增量、集合用途、独立复现和边界清晰”。开题报告应清楚说明二者的区别。
