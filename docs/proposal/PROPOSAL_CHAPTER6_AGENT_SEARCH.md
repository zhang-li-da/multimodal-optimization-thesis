# 第六章拟研究内容：智能体多模态搜索与探索—开发协同机制

修订日期：2026-09-26；设计版本 design-v2.0。本文更新研究定位，不改写 v1.2.3 已完成实验。详细方案见 [实验设计包](../chapter6/reviews/agent-search-20260926/README.md)。

## 6.1 研究问题与前序章节的联系

智能体在长期自动算法发现中，需要连续决定研究什么方向、从哪个候选继续、修改哪些模块，以及何时停止当前路径并转向其他方向。其外层决策空间具有组合复杂、评价昂贵、反馈不完全和潜在优质区域分散等特点。仅集中开发当前最好候选可能提前放弃仍有潜力的方向；持续提出新方向又可能难以积累足够的局部进展。

本章拟研究如何识别和维护多个潜在优质方向，在有限预算下给予局部进展合理的开发机会，并依据实际执行反馈动态协调探索与开发。多模态优化在这里提供组织搜索的思想；最终系统可以只输出一个最佳方案。多个程序的部署、集成或路由属于拓展用途，不作为本章成立的必要条件。

第三章的评价研究为区分质量、搜索分布与成本提供基础；第四章的多结构维护、局部开发和关系记忆为方向保留与资源分配提供启发；第五章关于质量与决策结构分别维护的研究支持对智能体候选的多维描述。本章需要重新验证这些思想在外层智能体决策空间中的作用，不能将内层路线或模型参数的多样性直接解释为外层搜索模式。

## 6.2 操作性定义和研究假设

将候选谱系、搜索方向和执行行为分组分别记录。方向依据实际模块结构、固定 probe 上的行为及可追踪的修改操作描述；它是有限证据下的工作定义，不预设为真实局部最优盆地。质量和未来收益独立评价，不能用最终成功反向定义当时的“正确方向”。

拟检验四个假设：多方向搜索能降低有害的过早集中；有限开发保护可避免过早放弃局部进展；实际反馈调度相对固定/时间调度提高预算效率；同一机制可以在不同任务中复用。每个假设均有单独对照和可收缩的结论边界。

## 6.3 拟议机制与现有实现

A 保留质量合格的候选出发点并关联方向描述；B 管理活跃方向的有限开发额度；M 记录执行结果、停滞、重现、局部进展和成本；调度器在开辟方向与继续开发之间分配资源。新设计拟采用初始保护、有限续额与全局预算共同约束，防止仅因未超过全局最好而提前放弃，也防止重复方案无限获取机会。

目前代码中的 A 仍是程序行为档案，B 是节点额度，M 主要记录标签级反馈；完整排序没有实现全局探索—开发的动态协调。可靠方向识别、模块级任务适配器、统一五策略接口与新的反馈调度均属于后续工作。候选公式和超参数只在开发集上选择，再冻结验证。

## 6.4 已完成研究基础

v1.2.3 已完成 MiniMax M3 的 16 次真实搜索、独立测试、原始归档和离线演示。FIFO 与完整排序平均 Test gap 为 5.9833% 和 6.1019%；103/128 个提案解析失败，18 次续开发没有多分支竞争。同历史审计的 128 次决策和提示一致，因此本批次未产生可识别的排序处理差异。

这些结果支持可追溯执行链路和故障定位，也说明输出完整性及搜索机会不足会阻碍方法检验。它们不证明完整排序有效或无效，也不作为下一版预期效应的估计。已有 demo 可用于展示真实研究过程；合成控制用例仅说明规则如何工作。

## 6.5 实验路线

先独立校准任务形态输出，解决 planner 截断；再核验方向描述和有限开发额度，观察自然搜索中的多方向竞争。核心策略比较包括单路径开发、广泛重启、固定多方向、预定时间调度和实际反馈调度。通过保护×反馈消融区分组件贡献，再对反馈对应和成本做专项检查。

TSP 从 14 城市回归测试扩到 50/100 城市开发、200 城市外推，并把扩大城市规模与开放构造/局部搜索/重启模块作为不同因素。大规模参考值单独计算，未经证明最优的结果使用相对参考解差距。

端到端验证接入 MLE-Bench，开展与 MLEvolve 同模型、同资源的适配比较；先开发任务验证链路，再预注册未见任务与多种子实验，最终争取覆盖完整基准。另用数学优化任务验证不同类型决策空间，并核对原始定义、可行性与独立验证器。更换骨干模型或资源配置的影响分开报告。

## 6.6 预期贡献和结果边界

预期贡献在于方向维护、局部开发保护和实际进展调度如何共同改善长期搜索。最终评价以独立质量、达到目标的概率和总资源效率为主，方向数量、熵和谱系深度用于解释。更多分支或更长轨迹本身不构成有效性证据。

若有限保护有效而复杂排序无增量，应保留简单机制；若跨任务不能重复，应明确适用范围。即使最终仅输出一个最佳算法，只要公平对照支持其发现质量或预算效率改善，本章核心主张仍可成立。当前是待检验的研究方案，不将候选机制写成已证实成果。
